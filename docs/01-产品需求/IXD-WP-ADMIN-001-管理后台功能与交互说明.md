# IXD-WP-ADMIN-001 管理后台功能与交互说明

**状态：** 已实现
**版本：** V0.3.0
**日期：** 2026-09-11
**关联需求：** PRD-WP-001
**原型工程：** `apps/admin-web`

## 1. 目标和边界

管理后台用于倾境壁纸的内容运营和兑换交付。WP-P07 已将登录、分类、壁纸、资源版本和发布流程接入 Java API；兑换码、兑换记录和设备权益在 WP-P08 接入。

- 仅设置一个管理员账号，不设计角色、菜单或数据权限。
- 页面通过 HTTP Repository 访问同源 `/api/v1`，开发服务器代理到本机 Java API。
- 登录会话使用 HttpOnly Cookie；CSRF Token 只保存在页面内存，前端不保存管理员密码。
- 上传文件由 API 校验并写入 FileStorage 本地 Adapter，页面刷新后继续从 MySQL 和资源目录读取。
- 兑换码、兑换记录和设备权益页面在 WP-P08 完成前显示明确的接口等待状态，不展示虚构数据。

## 2. 管理员登录

本地管理员通过 `./scripts/local-api.sh init-admin` 一次性初始化，仓库不提供默认密码。登录页覆盖必填检查、错误账号提示、成功进入工作台和刷新恢复会话。Java API 保存 BCrypt 密码哈希并签发会话，前端不把密码或 CSRF Token 写入持久化存储。

## 3. 页面与操作

| 页面 | 首轮功能 |
|---|---|
| 工作台 | 壁纸、发布、兑换额度和成功兑换统计；最近更新；快速入口。WP-P08 前兑换统计由真实 API 返回零值 |
| 分类管理 | 一级/二级树、搜索、新增、编辑、节点选择和同级排序；一级分类上传图标 |
| 壁纸管理 | 搜索、类型与状态筛选、资源完整度、编辑、发布、下架和二次确认删除 |
| 上传壁纸 | 一级/二级分类联动、类型选择、平台选择、分类型资源、1:2 客户端预览、必填校验 |
| 兑换码 | WP-P08 接入批次列表、生成数量、单码额度快照、完整码一次性复制或导出 |
| 兑换记录 | WP-P08 接入按兑换码、壁纸或设备检索，并按结果筛选 |
| 设备权益 | WP-P08 接入匿名设备的平台、已获得壁纸数和最后活跃时间 |

## 4. 壁纸上传模型

所有类型均填写：壁纸名称、联动选择一级与二级分类、排序值、列表封面、发布状态和适用平台。二级分类只能从当前一级分类的子节点中选择，不能自由输入。

### 4.1 分类节点规则

- 新增分类时先选择所属节点：根节点代表一级分类；选择已有一级分类则创建其二级分类。
- 一级分类显示在 App 首页金刚区，必须上传 PNG、JPG 或 WebP 图标，文件不超过 1 MB。
- 二级分类显示在对应分类列表的横向筛选栏，不设置图标。
- 分类保存后立即生效，不设置“创建后启用”复选框。

### 4.2 4D 分层壁纸

- 平台固定为 Android。
- 必填：列表封面、背景层、透明前景层。
- 选填：景深配置 JSON。
- 背景层建议 JPG 或 WebP；前景层建议 PNG 或支持透明通道的 WebP。
- 景深 JSON 用于后续配置各层随手机姿态移动的幅度。
- App 详情页直接加载背景层、透明前景层和景深参数合成 4D 效果，不上传独立预览视频。

### 4.3 动态壁纸

- Android 必填 MP4 动态视频。
- iOS 必填同一 Live Photo 的 MOV 与 JPEG 两个资源；该组合与当前本地上传校验器一致。
- HarmonyOS 必填按客户端契约打包的 ZIP 资源。
- 可同时勾选多个平台；系统按已选平台组合显示并校验资源字段。
- App 详情页直接播放当前设备对应的正式资源：Android 使用 MP4，iOS 使用 MOV。如浏览容器不支持 MOV，由服务端根据同一上传文件自动生成可播放转码，不要求管理员重复上传。
- HarmonyOS 资源包需按契约包含可提取的预览素材，由服务端在上传后自动解析。

### 4.4 静态壁纸

- 可选择 Android、iOS 和 HarmonyOS。
- 必填列表封面和静态高清原图。
- 客户端依据设备安全区域裁切，不在后台生成固定机型尺寸。

## 5. 保存与发布规则

1. “保存草稿”与“保存并发布”执行相同的资源必填检查，避免产生无法继续编辑的空内容。
2. 列表展示每张壁纸的必填资源完成数，例如 `3/3 已就绪`。
3. 已发布内容可以下架；下架保留内容和资源元数据。
4. 壁纸一旦产生资源版本，类型和平台组合即锁定；替换素材时创建新的不可变资源版本，发布成功后旧版本转为 `RETIRED`。
5. 无资源历史的草稿可二次确认后物理删除；已有资源历史或已下架的壁纸只能归档。

## 6. 兑换码规则

1. 兑换码不绑定具体壁纸，设备在剩余额度内可任选内容。
2. 每个批次记录 `兑换码数量 × 单码可兑换壁纸数`。
3. 单码额度在生成时形成快照，修改以后批次的默认额度不影响旧码。
4. 完整兑换码仅在生成结果弹窗出现一次，可复制或导出 CSV；关闭后列表只保留批次与使用统计。
5. 正式版由服务端生成高熵兑换码并只保存摘要，导出文件不长期留存在后台。
6. 兑换码没有启用或停用状态；有效性只由剩余额度和服务端校验结果决定。

## 7. HTTP Repository 接口边界

- `login`：管理员登录与会话。
- `categories` / `saveCategory`：分类列表与保存。
- `wallpapers` / `saveWallpaper`：壁纸列表、详情、资源版本和发布状态。
- `generateBatch` / `batches`：兑换码批次生成与统计，WP-P08 接入。
- `redemptions`：兑换流水查询，WP-P08 接入。
- `devices`：匿名设备及其权益查询，WP-P08 接入。
- 资源文件通过 API 上传到 FileStorage；当前使用本地 Adapter，后续可替换为对象存储 Adapter。

## 8. 已确认与后续验证重点

- 真实联调已覆盖错误登录、刷新恢复会话、两级分类、静态壁纸资源上传、发布、下架、重发和新资源版本发布。
- 4D 壁纸是否需要增加更多前景层，以及景深参数是否改成可视化编辑。
- iOS、HarmonyOS 资源格式最终以各平台客户端验证结果为准。
- 分类和壁纸列表需要的批量操作、分页和排序方式。
- 同设备权益自动恢复在 WP-P08 至 WP-P10 补齐；换机迁移不在 MVP 范围内。
