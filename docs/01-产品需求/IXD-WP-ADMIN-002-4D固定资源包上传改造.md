## 1. 为什么改

当前运营表单需要分别选择封面、背景、前景和配置。只有一个前景入口难以处理多层作品，也容易把不同版本的封面、图层、JSON 混在一起。

改为每件 4D 作品上传一个完整 ZIP，设计人员按固定目录交付，服务端统一检查并转换。现有 Android 图层配置和渲染器已支持 2～12 层，服务端输出继续使用该格式，App 无需因为上传方式变化而重新打包。

## 2. 运营人员准备什么

三层作品示例，ZIP 文件本身可以自由命名：

```text
wallpaper-4d.zip
├── cover.jpg
├── config.json
└── layers/
    ├── 01.png
    ├── 02.png
    └── 03.jpg
```

| 内容 | 用途与规则 |
|---|---|
| `cover.jpg` | 列表缩略图，提供完整合成画面；公开展示，建议使用适合列表的压缩版本 |
| `config.json` | 画布尺寸、陀螺仪参数和每层景深参数，固定字段示例见 API-007 |
| `layers/01` | 最前景；编号必须是两位数字，从 `01` 连续开始 |
| 最后一层 | 最远的背景，必须铺满画布；总数 2～12 层 |
| 前面的所有层 | PNG 或 WebP，保留透明通道；背景可以是 JPG、PNG 或 WebP |

所有图层的画布尺寸相同，透明留白也属于画布，不能把前景裁成小图。编号决定遮挡顺序；JSON 的景深决定移动幅度。完整校验规则以 API-007 为准。

选择目录内的 `cover.jpg`、`config.json`、`layers` 一起压缩，ZIP 根目录不要再套一层作品文件夹。

## 3. 管理后台修改范围

选择 4D 时，平台固定 Android。资源区显示一个“4D 固定资源包”文件框、目录说明和解析摘要；取消独立的列表封面、背景、前景、JSON 上传框。动态、静态的上传入口沿用当前规则。

基础信息仍填写名称、Slug、分类、排序、精选和版权说明。4D 封面从 ZIP 中取得，不能单独替换；更新封面也应交付完整 ZIP，以便封面和素材版本可追溯。

右侧 4D 预览标题使用“列表封面预览”。浏览器不解压、不模拟 4D。新选 ZIP 显示文件名和大小；保存并重新打开后显示服务端返回的封面、层数和尺寸。旧封面在替换 ZIP 尚未保存时可能仍可见，不代表新包已经校验成功。

## 4. 保存与发布

1. 新建时必须选择一个 ZIP，保存草稿与保存并发布均检查必填。
2. 保存时调用包导入 API，由服务端解压、校验，成功返回 `sourcePackageId` 对应的包描述和 `cover.id`。
3. 用 `cover.id` 保存壁纸基础信息，查找或创建 Android `LAYER_PARALLAX` 变体。
4. 用包 ID 创建资源版本，所有图层绑定及内部 JSON 由服务端生成。
5. 保存草稿后重新读取详情。保存并发布继续调用现有安全包制作与发布接口。
6. 全部请求成功才关闭编辑窗口并提示成功；包解析失败时不能继续创建或发布作品。

保存期间按钮显示忙碌状态。当前使用同步导入，上传请求超时为 60 秒，其余请求为 15 秒；服务端需在该时间窗口内响应。若后续改异步任务，需要同时扩展管理后台状态机，不能仅返回 `202`。

接口返回中文错误应指出具体文件，例如“layers/02.png 尺寸与画布不一致”。当前错误显示在消息提示中，失败保留表单。基础信息已保存后，后续失败保留作品 ID 和资源进度，重试继续同一作品。超时需先刷新确认结果。

## 5. 更新和历史数据

- 已经存在的逐层上传作品仍能展示、播放、下架及重新发布。
- 有 `READY` 或 `PUBLISHED` 4D 版本时，编辑基础信息可以不选 ZIP，沿用现有素材与封面。资源完整度计为可用，不能因为缺少新字段就显示资源丢失。
- 已有新格式包且没有更换时，沿用包 ID 和资源版本，避免重复上传或创建版本。
- 替换时上传整个 ZIP，生成下一不可变资源版本；已交付版本保持可追溯。
- 移除文件框中选择的 ZIP 表示取消本次替换；已有素材仍保留。新作品移除 ZIP 后不能保存。
- 不提供从浏览器逐项修改图层的入口；旧数据无需为了升级上传入口批量迁移。
