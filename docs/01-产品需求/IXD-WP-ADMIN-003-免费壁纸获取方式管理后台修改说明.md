# IXD-WP-ADMIN-003 免费壁纸获取方式管理后台修改说明

**日期：** 2026-09-16

**状态：** 已实施，待业务验收

**对应任务：** PM-002 / WP-UI10

**接口交接：** [API-012 免费壁纸获取方式接口交接说明](../04-接口设计/API-012-免费壁纸获取方式接口交接说明.md)

## 1. 产品规则

“免费”是壁纸的获取方式，不是分类，也不是 4D、动态或静态等资源类型。

- 所有壁纸默认需要兑换，值为 `REDEEM`。
- 只有运营人员明确选择“免费”的壁纸才免兑换，值为 `FREE`。
- 一张壁纸仍然只属于现有一级、二级分类；它可以同时是 A 分类、4D 类型、精选和免费。
- 不新建“免费”分类，不复制作品，也不通过标题、标签或价格为零推断免费。
- 免费壁纸不消耗兑换码，不自动创建设备权益，也不自动出现在“我的已获得”中。

## 2. 新建与编辑表单

在壁纸基础信息区增加必填项“获取方式”，使用单选按钮：

| 页面文案 | API 值 | 说明 |
|---|---|---|
| 需要兑换 | `REDEEM` | 默认选中；用户先兑换获得权益，再下载 |
| 免费 | `FREE` | 用户可直接下载和设置，不显示兑换流程 |

交互要求：

1. 新建作品默认选中“需要兑换”。
2. 编辑时使用详情接口返回值回填，不能根据分类或历史兑换记录猜测。
3. 保存时和名称、分类等基础字段一起提交 `accessType`；它不属于变体、素材版本或 4D 配置。
4. 未选择时前端阻止提交并提示“请选择获取方式”。管理后台不能默认为免费。
5. 保存、并发版本和 `If-Match` 规则沿用当前作品编辑流程。

建议放在“精选/排序”附近，避免运营人员把它误认为资源格式设置。

## 3. 列表与筛选

管理端壁纸列表增加：

- “获取方式”列或紧邻标题的状态标识：`免费` / `需兑换`。
- 筛选项：全部、免费、需兑换，对应省略参数、`FREE`、`REDEEM`。
- 免费作品使用醒目的“免费”标识；需兑换可以显示普通文字，不能只依赖颜色。

分类、类型、状态、关键词等现有筛选保持不变，获取方式可以和它们组合查询。

## 4. 已发布作品修改规则

获取方式是作品级业务元数据，允许按现有作品编辑流程修改，不生成新的素材版本：

- `REDEEM → FREE`：保存成功后公开目录立即显示免费，后续下载不再要求权益；已有权益记录保留。
- `FREE → REDEEM`：保存成功后新下载必须有权益；设备已经安装的本地资源不删除；免费期间不会补建权益。
- 已有兑换码批次不随作品改为免费而删除。对免费作品提交兑换码时 API 应拒绝且不扣额度。
- 兑换记录页需要识别 `WALLPAPER_FREE`，显示“壁纸已免费”，并允许按该结果筛选；该结果的额度变化始终为 0。
- 归档作品仍不可编辑；下架和发布状态规则保持现状。

修改结果以 API 返回的作品详情为准，保存成功后重新读取详情和列表，避免本地乐观状态与服务端不一致。

## 5. 前台映射

前端已经按以下规则接入：

- 首页“精选壁纸”第二个标签为“免费壁纸”，请求 `accessType=FREE`。
- 首页、分类和搜索结果中的免费作品显示“免费”标识。
- 免费详情跳过权益查询和兑换弹窗，直接进入下载；需兑换作品保持原流程。
- 客户端只有在值严格等于 `FREE` 时才视为免费；字段缺失、`REDEEM` 或未知值都按需兑换处理。

因此后台必须提交稳定枚举值，不能提交中文、布尔值或空字符串。

## 6. 管理后台验收

1. 新建表单默认“需要兑换”，保存后刷新仍为 `REDEEM`。
2. 新建免费静态、动态和 4D 作品均可成功，证明获取方式与资源类型无关。
3. 同一分类中免费与需兑换作品可以并存，列表标识正确。
4. 获取方式筛选可与分类、类型和状态组合，并保持分页正确。
5. `REDEEM ↔ FREE` 修改遵守 ETag 冲突保护，刷新后显示服务端最终值。
6. 免费作品发布后前台免费标签可查到，卡片显示“免费”，详情不弹兑换。
7. 免费改回需兑换后，未获得权益的设备不能继续申请正式下载票据。
8. 编辑获取方式不会新建资源版本、改写 4D 配置或删除兑换/权益历史。
