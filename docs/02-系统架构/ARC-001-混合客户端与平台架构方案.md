# ARC-001 混合客户端与平台架构方案

**状态：** 已确认
**日期：** 2026-09-10
**关联需求：** PRD-WP-001

## 1. 决策

正式 App 从第一版开始使用混合架构：

- Flutter 负责导航、内容列表、详情、兑换、下载状态、我的壁纸和通用设计系统。
- Android 原生插件负责设备能力、传感器、资源安装、动态壁纸渲染和系统设置入口。
- iOS、HarmonyOS 从第一版就拥有独立的平台接口和资源变体，不把 Android 的 WallpaperService 概念写入共享业务层。
- 当前 Java Android 工程属于技术验证项目，不直接演变为正式 App；其中已验证的传感器、分层渲染和 WallpaperService 逻辑迁入 Android 插件。

该决策保证将来接入 iOS、HarmonyOS 时不重做内容模型、兑换逻辑、API 和后台。各平台受系统公开能力限制，不能保证三端拥有完全相同的设置方式和动态效果。

## 2. 沿用考试系统的技术基线

| 层 | 技术方案 | 复用原则 |
|---|---|---|
| H5 原型 | Vue 3、TypeScript、Vite、Vue Router、Pinia、Vant | 先用 Mock Repository 确认移动端页面和交互 |
| 管理后台 | Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router | 使用精简后台外壳，先 Mock 后切 HTTP Repository |
| 正式 App | Flutter stable、Dart | 共享业务界面和状态管理 |
| 平台能力 | Flutter federated plugin + 类型化通道 | Android 使用 Kotlin；iOS 使用 Swift；HarmonyOS 使用 ArkTS/平台适配实现 |
| 服务端 | Java 21、Spring Boot 4.1.x、Spring Security、MyBatis-Plus、Flyway | 模块化单体，不拆微服务 |
| 数据 | MySQL 8.4 LTS、Redis 7.4 Extended | MySQL 保存业务事实；Redis 只做缓存、限流、短时票据和幂等协调 |
| 文件 | S3 兼容对象存储 + CDN | 私有桶保存原包，授权后返回短时下载票据 |
| 契约 | OpenAPI 3 | 管理端、H5、Flutter 共用一份接口契约 |
| 部署 | Docker + Nginx | 区分本地、测试和生产环境 |

具体补丁版本在各工程创建时锁定，不使用浮动版本。

## 5. Flutter 与原生插件边界

共享层只使用平台无关接口。建议使用 federated plugin 结构，并通过 Pigeon 或等价类型化通道生成 Flutter 与原生通信代码。

### 5.1 平台接口

    WallpaperPlatform
    ├── getCapabilities()
    ├── getAnonymousDeviceEvidence()
    ├── preparePreview(variant, localPackage)
    ├── startPreview(session)
    ├── stopPreview()
    ├── installPackage(packageDescriptor)
    ├── applyWallpaper(installedId, requestedTarget)
    ├── queryAppliedWallpaper()
    └── openPlatformHelp(reason)

### 5.2 统一能力返回

| 字段 | 说明 |
|---|---|
| platform | android、ios、harmonyos |
| osVersion | 系统版本 |
| supportedTypes | static、layer_parallax、video、live_photo、theme_package |
| supportedTargets | home、lock、both |
| sensorAvailable | 是否有可用姿态传感器 |
| canApplyDirectly | 是否可进入平台正式设置流程 |
| requiresMediaExport | 是否必须先保存到系统相册 |
| capabilityNotes | 面向用户的适配说明编号 |

Flutter 根据能力结果展示按钮，不根据机型名称自行猜测。

### 5.3 Android 首版实现

Android 插件包含：

- WallpaperService 及 Engine。
- 姿态传感器采样、低通滤波和生命周期控制。
- 分层资源加载、裁切、位移和降级渲染。
- 资源包签名、哈希、解密和原子安装。
- Android Keystore 安装凭据。
- WallpaperManager 系统预览入口。
- 桌面、锁屏和两者的能力探测及厂商差异提示。

Android 系统动态壁纸由 WallpaperService 提供，最终应用范围以系统确认页面为准。

### 5.4 iOS 扩展边界

iOS 插件预留以下实现：

- 静态图保存或系统分享。
- Live Photo 预览和保存到照片图库。
- 跳转或展示系统设置说明。
- iOS 平台资源校验和缓存。

iOS 公开能力允许应用构造、预览和保存 Live Photo，但没有与 Android WallpaperService 等价的第三方常驻壁纸服务。实现时必须按目标 iOS 版本重新验证系统规则，Flutter 共享层不能假设能够静默设置壁纸。

### 5.5 HarmonyOS 扩展边界

HarmonyOS 插件预留以下实现：

- ArkTS 平台桥接、传感器和文件能力。
- 静态、视频或主题包变体适配。
- 华为主题中心/主题引擎允许的动态壁纸交付流程。
- 平台能力不足时的导出和设置指引。

华为主题体系公开资料包含视频桌面、可交互桌面、多层和重力感应等能力，但内容制作、应用内设置和主题市场分发是不同通道。实施 HarmonyOS 前必须在目标系统版本与上架渠道做独立 PoC。

## 6. 内容与平台变体模型

“壁纸作品”和“平台文件”分离：

    Wallpaper
      ├── 基础信息、分类、封面、授权状态
      └── WallpaperVariant[]
          ├── platform
          ├── resourceType
          ├── minimumOsVersion
          ├── renderProfile
          └── ResourceVersion[]

示例：

| 作品 | 平台 | 资源类型 | 文件 |
|---|---|---|---|
| 山间云海 | universal | static | WebP/JPEG |
| 山间云海 | android | layer_parallax | 4DWP 分层包 |
| 山间云海 | ios | live_photo | 照片 + paired video |
| 山间云海 | harmonyos | theme_package | 经平台校验的主题资源 |

兑换发生在 Wallpaper 作品层，下载时由服务端根据设备能力选择已发布的平台变体。兑换码本身不绑定平台。

## 7. 匿名设备与权益模型

无用户账号时，设备就是权益主体：

    AnonymousDevice
      ├── serverDeviceId
      ├── platform
      ├── protectedFingerprint
      ├── installationPublicKey
      ├── supportCode
      └── status

    DeviceEntitlement
      ├── deviceId
      ├── wallpaperId
      ├── sourceRedemptionId
      ├── status
      └── grantedAt

Android 首次运行生成安装密钥对，并将公钥和设备证据发送给服务端。服务端保存不可逆的受保护指纹，不保存可直接展示的系统标识。同一签名 App 在同一 Android 用户且没有恢复出厂时，重装通常可以重新关联；安装密钥会轮换。

恢复出厂、系统用户变化、ROM 变化或换机后，系统标识可能变化。无账号方案无法自动证明这仍是同一个人，此时通过“设备支持编号 + 客服审核 + 管理端权益迁移”恢复。迁移成功后旧设备权益失效。

## 8. 兑换额度快照

关键字段：

| 对象 | 字段 | 规则 |
|---|---|---|
| 平台设置 | defaultQuotaPerCode | 只作为新建批次默认值 |
| 兑换码批次 | quotaPerCodeSnapshot | 创建批次时确定 |
| 单个兑换码 | totalQuota | 从批次快照复制，生成后不随默认值变化 |
| 单个兑换码 | usedQuota | 成功创建新设备壁纸权益时加 1 |
| 兑换记录 | delta | 新兑换为 1，重复获得为 0 |
| 设备权益 | deviceId + wallpaperId | 全局业务唯一，不重复收费 |

一次兑换事务必须执行：

1. 锁定或条件更新兑换码。
2. 查询当前设备是否已有该壁纸权益。
3. 已有权益则返回成功且不扣额度。
4. 没有权益且余额充足时，同时创建兑换记录、设备权益并增加 usedQuota。
5. 任一步失败则整体回滚。
6. 客户端重试必须复用 Idempotency-Key。

## 9. 受保护下载流程

~~~mermaid
sequenceDiagram
    participant A as Flutter App
    participant N as 平台原生插件
    participant S as Java API
    participant O as 私有对象存储

    A->>S: 请求下载票据（设备会话、壁纸版本）
    S->>S: 校验 App、设备、权益、版本和频率
    S-->>A: 短时票据、文件摘要、加密信封
    A->>O: 使用短时签名地址下载密文
    O-->>A: 加密资源包
    A->>N: 校验、解密并原子安装
    N-->>A: 安装结果
    A->>N: 请求设置壁纸
    N-->>A: 打开系统确认页面
~~~

公开列表和详情接口不返回对象存储 Key、永久 URL 或内容密钥。

## 10. 资源保护结论

可以显著提高批量盗取成本，但不能承诺资源绝对无法提取。

首版必须实现：

- 全链路 TLS。
- 匿名设备会话和安装密钥签名挑战。
- 权益校验后签发 60 至 120 秒短时下载票据。
- 私有对象存储和不可枚举对象 Key。
- 资源包 AES-GCM 加密、manifest 签名、SHA-256 校验。
- App 私有目录保存，动态资源不写系统相册。
- 接口和下载限流、异常设备停用、审计和密钥轮换。
- 服务端只保存兑换码 keyed hash；完整兑换码只在批次生成后一次性交付。

后续增强：

- Android 硬件证明或渠道完整性能力。
- 证书公钥固定及备用公钥轮换。
- 每台设备不同的内容密钥信封。
- 资源隐形水印和泄露样本追踪。
- Root、Hook 和调试风险检测。

静态壁纸一旦成为系统可见图像，仍可被截图或从受控设备提取；动态资源运行时也可能在 Root/Hook 环境被截获。安全目标是阻止直接抓包、批量爬取和链接转卖。

## 11. 模块化单体边界

服务端模块：

| 模块 | 职责 |
|---|---|
| adminidentity | 管理员会话、角色和权限 |
| catalog | 分类、壁纸、平台变体和发布 |
| asset | 上传、校验、版本、对象存储 |
| device | 匿名设备、安装密钥、恢复和停用 |
| redemption | 兑换码批次、核销、额度和幂等 |
| entitlement | 设备壁纸权益和迁移 |
| delivery | 下载票据、加密信封和限流 |
| audit | 管理操作、安全事件和业务追踪 |

模块之间通过明确的应用服务调用，不让 Controller 直接访问其他模块的 Mapper。

## 12. 不变量

1. 公开 API 永远不返回永久资源地址。
2. 客户端不能自行声明兑换成功、设备身份或下载权益。
3. 同一设备对同一壁纸最多存在一份有效权益。
4. 重复兑换已拥有壁纸不消耗额度。
5. 兑换码 usedQuota 永远不大于 totalQuota。
6. 修改默认额度不修改任何历史批次或兑换码。
7. 已发布资源版本不可原地替换文件。
8. 平台能力由插件返回，Flutter 页面不硬编码 Android 规则。
9. MySQL 是权益、额度、发布和审计的唯一事实来源。
10. iOS、HarmonyOS 接入不得要求修改 Android 已发布资源的语义。

## 13. 主要风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 无账号恢复能力有限 | 恢复出厂或换机无法自动证明归属 | 客服审核后做受审计迁移 |
| 厂商动态壁纸行为不同 | 锁屏、桌面可选项不一致 | 真机矩阵检测并以系统页面为准 |
| iOS 能力与 Android 不对等 | 无法提供相同常驻视差服务 | 使用平台变体和能力驱动 UI |
| HarmonyOS 分发通道未验证 | 可能需要主题市场而非普通 App | 独立 PoC 后实现适配器 |
| IP 素材未经授权 | 应用市场下架或投诉 | 正式发布只使用原创或已授权素材 |
| 加密仍可能被逆向 | 高价值资源泄露 | 短时票据、设备密钥、水印和风控共同提高成本 |
