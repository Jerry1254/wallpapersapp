# DM-001 统一领域模型

**状态：** 已确认  
**版本：** V1.7.0

**日期：** 2026-09-15
**关联需求：** PRD-WP-001、IXD-WP-H5-001、IXD-WP-ADMIN-001  
**关联架构：** ARC-001、SEC-001  
**适用范围：** H5、管理后台、Java API、Flutter App

## 1. 目的与约束

本文统一各端对分类、壁纸、平台资源、匿名设备、兑换码和权益的称呼及业务含义。数据库设计和 OpenAPI V1 必须以本文为语义基线；页面字段可以按场景裁剪，但不能自行改变业务事实。

当前阶段的边界如下：

- 一个管理员账号，不设计租户、角色和权限模型。
- 分类只允许两级。一级分类可上传图标，二级分类不保存图标。
- 兑换码不提供启用或停用状态，也不设置有效期；能否兑换只由码是否存在及剩余额度决定。
- 用户不登录，权益绑定匿名设备。同一设备再次进入可直接查询已获得壁纸，不再输入兑换码。
- H5 使用测试设备凭据验证数据闭环；正式 App 使用平台安全存储保存设备凭据。
- 资源先保存在 API 服务器本地目录，通过存储接口访问。数据库不保存绝对文件路径。
- H5 暂不实现真实 4D、动态壁纸和系统设置能力；正式 App 复用相同内容、兑换、权益和下载契约。
- 当前不实现换机权益迁移。客服入口用于业务咨询；“我的”页面不展示设备编号。

## 2. 领域模块

V1.7 将 `ParallaxSourcePackage` 统一为客户端原始配置来源。管理员上传固定 4D ZIP，API 校验文件安全、格式版本、画布和图层索引后，把 `config.json` 原始字节保存为 `PARALLAX_CONFIG`；算法字段不拆库、不转换，格式版本不低于 2 且不设服务端白名单。版本通过 `source_package_id` 保留来源，重新上传和替换都不覆盖历史版本。正式包仍为安全容器 format 2，试用包仍为 format 3。

| 模块 | 负责的业务事实 | 不负责 |
|---|---|---|
| `adminidentity` | 单管理员凭据、登录会话、登录失败限制 | 角色、菜单权限、多租户 |
| `catalog` | 分类、壁纸作品、平台变体、发布状态、排序 | 文件字节、设备能力判断 |
| `asset` | 文件元数据、存储键、哈希、格式、校验结果、资源版本 | 公开 URL、权益判断 |
| `tutorial` | 五个固定壁纸设置教程槽位、视频引用、启停和排序 | 新增教程类型、正式壁纸交付 |
| `parallax` | 固定 4D 源包导入、2～12 层文件映射、原始配置保存、来源关联、失败存储清理 | 算法参数解释、客户端渲染、正式包签名和交付 |
| `device` | 匿名设备、设备凭据、设备会话 | 用户账号、手机号身份 |
| `redemption` | 兑换码批次、码额度快照、核销事件、幂等 | 支付订单、用户账户余额 |
| `entitlement` | 某设备已获得某壁纸的长期权益 | 客户端下载和设置状态 |
| `delivery` | 下载描述、短时票据、下载审计、频率限制 | 永久公开资源地址 |
| `audit` | 管理写操作和重要安全事件 | 普通页面浏览统计 |

Controller 只调用本模块应用服务或明确的跨模块用例，不直接访问其他模块的 Mapper。

## 3. 统一术语

### 3.1 内容与资源

| 统一术语 | 含义 | 禁止混用的概念 |
|---|---|---|
| 分类 `Category` | 壁纸的两级业务分类节点 | 推荐、静态等页面筛选条件 |
| 一级分类 `Root Category` | 顶部金刚区的业务分类，可配置图标 | 二级筛选按钮 |
| 二级分类 `Child Category` | 从属于一个一级分类的列表筛选节点，不配置图标 | 标签、平台 |
| 壁纸作品 `Wallpaper` | 用户兑换和持有权益的稳定对象 | 某个平台文件、某个版本 |
| 平台变体 `WallpaperVariant` | 同一作品在指定平台和资源类型下的交付形态 | 作品本身 |
| 资源版本 `ResourceVersion` | 一个平台变体的一组不可变文件版本 | 可原地覆盖的上传目录 |
| 资源文件 `Asset` | 单个物理文件的元数据和存储引用 | 公开 URL、数据库 BLOB |
| 资源角色 `AssetRole` | 文件在某资源版本中的用途，例如封面、前景、背景 | MIME 类型 |
| 推荐 `Featured` | 运营排序形成的系统视图，不是分类节点 | 一级分类“推荐” |
| 静态筛选 `Static Filter` | 按资源类型形成的系统视图，不是分类节点 | 一级分类“静态” |
| 设置教程 `WallpaperTutorial` | 平台和壁纸类型固定映射到的公开 MP4 教程 | 壁纸资源版本、可自由新增的 CMS 栏目 |

当前原型中的“推荐”和“静态”分类在接入真实数据时改为系统筛选：推荐依据 `featuredRank`，静态依据可用变体的 `resourceType`。一个壁纸作品只保存一组真实分类归属，不为展示入口重复造分类数据。

### 3.2 设备、兑换与交付

| 统一术语 | 含义 | 规则 |
|---|---|---|
| 匿名设备 `AnonymousDevice` | 无账号场景下的权益主体 | 服务端分配不透明 ID |
| 设备凭据 `DeviceCredential` | 客户端证明其可代表匿名设备的材料 | H5 和 App 实现不同，API 语义一致 |
| 设备会话 `DeviceSession` | 设备凭据换取的短期访问会话 | 放在 Redis，可撤销、可过期 |
| 兑换码批次 `CodeBatch` | 一次批量生成行为及额度快照 | 不保存启停状态和有效期 |
| 兑换码 `RedemptionCode` | 可跨平台使用、按成功新增权益消耗额度的凭证 | 数据库只保存 keyed hash 和掩码信息 |
| 兑换事件 `RedemptionEvent` | 一次兑换意图的不可变结果记录 | `delta=1` 表示新增权益，`delta=0` 表示已拥有 |
| 设备权益 `DeviceEntitlement` | 某匿名设备已获得某壁纸的服务端事实 | 同一设备和壁纸最多一条有效权益 |
| 下载票据 `DownloadTicket` | 通过权益校验后签发的短期交付许可 | 不作为永久业务事实 |
| 下载事件 `DownloadEvent` | 下载票据签发或使用结果的审计记录 | 不代表壁纸已经设置成功 |

“已获得”是服务端权益状态。“已下载”“已安装”“已设置”和“两分钟试用”是客户端本地状态，不进入服务端权益模型，也不影响兑换额度。

### 5.1 聚合及唯一事实源

| 聚合根 | 内部对象 | 业务唯一键 | 事实源 |
|---|---|---|---|
| `Category` | 无 | `slug` | 分类层级、名称、排序、图标引用 |
| `Wallpaper` | `WallpaperVariant`、`ResourceVersion`、`ResourceBinding` | `slug` | 作品分类、发布状态、平台资源版本 |
| `Asset` | 无 | `storageKey`、`sha256` | 文件元数据和校验结果 |
| `WallpaperTutorial` | 无 | 固定 `tutorialKey` | 教程视频引用、启停、排序和乐观锁版本 |
| `AnonymousDevice` | `DeviceCredential` | 服务端设备 ID；凭据指纹唯一 | 设备身份和会话归属 |
| `CodeBatch` | `RedemptionCode` | 批次号；码摘要唯一 | 每码额度快照和已用额度 |
| `DeviceEntitlement` | 无 | `deviceId + wallpaperId` | 设备已获得壁纸 |
| `RedemptionEvent` | 无 | `idempotencyKey` | 一次兑换意图的最终结果 |

推荐位、平台列表、兼容性、壁纸数量、使用进度、剩余额度和“已获得”均由上述事实计算或构建读模型，不重复作为可独立修改的数据事实。

## 6. 核心对象定义

### 6.1 Category

| 字段 | 语义 |
|---|---|
| `id` | 字符串形式的 Long ID |
| `parentId` | 一级分类为空，二级分类指向一级分类 |
| `name` / `slug` | 展示名 / 稳定业务标识 |
| `iconAssetId` | 一级分类必填，二级分类必须为空 |
| `sortOrder` | 同一父节点内的顺序 |
| `createdAt` / `updatedAt` | UTC 时间戳 |
| `version` | 乐观锁版本 |

分类没有启用、停用复选框。被已发布壁纸引用时不可硬删除；管理员应先调整引用或下架内容。

### 6.2 Wallpaper 与 WallpaperVariant

`Wallpaper` 在领域层保存作品级字段：`title`、`slug`、`kind`、选中的分类、`coverAssetId`、`featuredRank`、`sortOrder`、`copyrightNote`、`status`、时间字段和乐观锁版本。管理请求可传联动选择的 `rootCategoryId` 和 `childCategoryId`；数据库只保存最深选中的 `categoryId`，一级节点通过最多一跳关系推导，避免两列不一致。

`WallpaperVariant` 保存平台交付字段：`wallpaperId`、`platform`、`resourceType`、`minimumOsVersion`、能力约束和当前已发布资源版本。一个作品可拥有多个平台变体，但相同作品、平台和资源类型只能有一个变体。

`platforms` 不作为 Wallpaper 的可写数组；公开 API 中的平台集合由已发布变体计算。`compatible` 不存库，由设备平台、能力和当前变体计算。

### 6.3 Asset 与 ResourceVersion

`Asset` 至少保存：`storageKey`、原始文件名、MIME、扩展名、上传用途 `purpose`、字节数、SHA-256、可选媒体时长、校验状态和创建时间。V4 之前的资产 `purpose` 可为空，新上传必须记录。`storageKey` 是随机且不可枚举的相对键，应用通过 `FileStorage` 读取；任何数据库字段都不得保存服务器绝对路径。

`ResourceVersion` 保存语义版本、处理状态、发布时间和 manifest 摘要。文件通过 `ResourceBinding(versionId, assetId, role, ordinal)` 绑定。已发布版本不可替换绑定或修改文件摘要；更新资源必须创建新版本。

### 6.4 壁纸设置教程

`WallpaperTutorial` 只有 `ANDROID_PARALLAX_4D`、`ANDROID_DYNAMIC`、`STATIC`、`HARMONYOS_DYNAMIC`、`IOS_DYNAMIC` 五个固定 key。标题、平台和壁纸类型由服务端常量决定；MySQL 只保存 `videoAssetId`、`enabled`、`sortOrder`、时间和 `version`。

只有 `purpose=TUTORIAL_VIDEO`、`validationStatus=READY`、`mimeType=video/mp4` 的资产能绑定教程。客户端只看到已启用且视频有效的项目，通过带 `version` 的公开 URL 读取支持 Range 的字节流。更新教程不改动壁纸资源版本或用户权益。

### 6.5 CodeBatch 与 RedemptionCode

`CodeBatch` 保存批次名、批次号、生成数量、`quotaPerCodeSnapshot`、创建人和创建时间。它没有启停状态和有效期。

`RedemptionCode` 保存 `codeHash`、HMAC 密钥版本、掩码尾号、`totalQuota`、`usedQuota`、时间字段和乐观锁版本；当前实现没有逐码盐字段。完整明文码仅在一次性交付文件中短暂存在，不写数据库和日志。

兑换码的展示状态是派生值：

- `AVAILABLE`：`usedQuota < totalQuota`。
- `EXHAUSTED`：`usedQuota = totalQuota`。

不提供管理员手动改变码状态的接口。

### 6.6 AnonymousDevice 与 DeviceEntitlement

`AnonymousDevice` 保存服务端 ID、平台、App 安装范围、受保护的设备证据摘要、最近活跃时间和内部安全状态。设备 ID 不在“我的”页面展示。H5 的本地测试 Provider 只能用于开发与验收环境，生产 App 通过 Android Keystore 或对应平台安全存储持有凭据。

`DeviceEntitlement` 保存 `deviceId`、`wallpaperId`、来源兑换事件、获得时间和内部状态。同设备重新建立会话后按服务端设备 ID 查询原权益；重复下载不消耗兑换码额度。

MVP 不实现换机迁移。若后续增加客服找回，必须单独定义归属证明、迁移事务和审计流程，不能仅凭公开设备编号迁移权益。

## 7. 状态机

### 7.1 壁纸作品

~~~mermaid
stateDiagram-v2
    [*] --> DRAFT
    DRAFT --> PUBLISHED: 校验通过并发布
    DRAFT --> [*]: 未被引用时删除
    PUBLISHED --> OFFLINE: 下架
    OFFLINE --> PUBLISHED: 重新发布有效版本
    DRAFT --> ARCHIVED: 归档
    OFFLINE --> ARCHIVED: 归档
~~~

- `PUBLISHED`：公开目录可见并允许新兑换。
- `OFFLINE`：公开目录不可见，不允许新兑换；已有权益是否继续下载由下架原因策略决定。
- `ARCHIVED`：只保留历史事实，不直接恢复；需复制为新草稿。
- 硬删除只允许未发布且没有资源、权益或审计引用的草稿。

### 7.2 资源版本

~~~mermaid
stateDiagram-v2
    [*] --> UPLOADING
    UPLOADING --> VALIDATING: 文件写入完成
    UPLOADING --> REJECTED: 写入失败
    VALIDATING --> READY: 校验通过
    VALIDATING --> REJECTED: 校验失败
    READY --> PUBLISHED: 随壁纸发布
    PUBLISHED --> RETIRED: 新版本接替或内容归档
~~~

上传文件先进入隔离暂存区，校验通过后原子移动到正式存储键。文件 IO 和耗时校验不得放在数据库长事务中。

### 7.3 兑换

兑换码没有持久化状态机，是否可用实时由额度计算。每个 `RedemptionEvent` 只有一个最终结果：

| 结果 | 含义 | `delta` |
|---|---|---|
| `GRANTED` | 新建设备权益并扣减一次额度 | 1 |
| `ALREADY_OWNED` | 同设备已拥有同一壁纸 | 0 |
| `CODE_NOT_FOUND` | 兑换码摘要不存在 | 0 |
| `CODE_EXHAUSTED` | 兑换码没有剩余额度 | 0 |
| `WALLPAPER_UNAVAILABLE` | 壁纸未发布或不允许新兑换 | 0 |
| `FAILED` | 服务端处理失败并已回滚 | 0 |

相同 `deviceId + idempotencyKey` 必须返回相同最终结果。网络超时不是新的兑换意图，客户端重试必须复用原 Idempotency-Key。

## 8. 跨端字段映射

| 当前原型字段 | 统一来源 | 接入真实 API 后的处理 |
|---|---|---|
| 管理端 `wallpaper.platforms[]` | 已发布 `WallpaperVariant` | 改为只读派生字段 |
| 管理端 `wallpaper.resources` | 资源版本与绑定 | 按平台和资源类型编辑，不整包直写作品 |
| H5 `categories[]` | 选中分类的一跳根节点 | 一张作品只返回一个一级分类摘要 |
| H5 `subcategories[]` | 选中的二级节点 | 返回零或一个二级分类摘要 |
| H5 `compatible` | 当前设备能力 + 已发布变体 | 由 API 能力描述和客户端 Provider 计算 |
| H5 `ownedIds` | `DeviceEntitlement` | 从权益 API 获取 |
| H5 `downloadedIds` / `appliedId` | 客户端本地状态 | 不同步为服务端业务事实 |
| 页面 `coverUrl` | Asset 受控读取结果 | API DTO 生成，不保存为作品永久 URL |
| 列表 `wallpaperCount` | 分类下已发布作品计数 | 查询或读模型计算 |
| 批次 `usagePercent` | `sum(usedQuota) / sum(totalQuota)` | DTO 计算 |

Java `Long` ID 在所有 JSON DTO 中都返回字符串。时间使用 UTC 存储，API 使用带时区的 ISO 8601 字符串。

## 9. 业务不变量

1. 分类层级最多两级，不允许环；一级分类必须有图标，二级分类不得保存图标。
2. 一个壁纸必须归属一个一级分类；选择二级分类时，该节点必须属于所选一级分类。
3. 已发布壁纸必须有可用封面，以及至少一个校验通过并已发布的平台资源版本。
4. `PARALLAX_4D` 在 MVP 只允许 Android `LAYER_PARALLAX` 变体，且前景、背景、配置角色完整。
5. `DYNAMIC` 根据平台选择 `VIDEO`、`LIVE_PHOTO` 或 `THEME_PACKAGE`；后台直接使用正式资源预览，不额外要求预览 MP4。
6. 已发布资源版本不可原地覆盖；新文件、新 manifest 或新哈希必须生成新版本。
7. 公开目录和未获权详情不得返回存储键、绝对路径、完整正式资源、内容密钥或永久下载地址。
8. 兑换码 `usedQuota` 必须满足 `0 <= usedQuota <= totalQuota`，额度快照生成后不可修改。
9. 同一设备与同一壁纸最多存在一份有效权益；重复兑换返回成功且 `delta=0`。
10. 新增权益、额度扣减和兑换事件必须在一个数据库事务中提交或回滚，并通过行锁或条件更新防止并发超额。
11. 完整兑换码不持久化、不写日志；查询和核销使用服务端 keyed hash。
12. MySQL 是分类、发布、额度、权益和审计的唯一事实源；Redis 丢失不能造成这些业务事实丢失。
13. 客户端不能声明自己已获得壁纸，也不能通过传入设备 ID 访问其他设备数据；设备范围从已认证会话取得。
14. 所有管理写操作记录管理员、请求 ID、对象、动作、结果和时间；审计事件不可由普通编辑接口修改。
15. 文件写入、媒体探测和第三方调用不占用数据库长事务；失败的暂存文件由补偿任务清理。

## 10. 主要事务边界

### 10.1 兑换事务

1. 从设备会话取得 `deviceId`，锁定设备行串行化同设备写入，再用非锁定读读取或创建幂等记录，避免不存在记录的范围锁。
2. 查询 `deviceId + wallpaperId` 权益；已有权益写入或返回 `ALREADY_OWNED`，不改额度。
3. 校验作品允许新兑换；不存在的作品返回 404 并整体回滚，已存在但不可兑换的作品保存最终拒绝结果。
4. 锁定兑换码行并校验剩余额度。
5. 不存在则创建设备权益、写 `GRANTED` 事件并将 `usedQuota` 增加 1。
6. 任一步失败整体回滚；相同幂等键返回已保存结果。

V1.0.1 在 WP-P12 对齐已验证的锁顺序、HMAC 字段和缺失作品响应，不新增领域实体或业务事实；API DTO 字段仍以 OpenAPI 为准。

### 10.2 资源上传与发布

1. 文件先写隔离暂存目录并计算哈希。
2. 在事务外完成格式、尺寸、解压边界和资源角色校验。
3. 校验通过后原子移动文件，短事务登记 Asset、资源版本和绑定。
4. 发布事务再次校验版本完整性，将版本设为不可变并切换作品引用。
5. 数据库失败时记录待清理存储键；文件失败时不提交资源元数据。

### 10.3 下载授权

1. 从设备会话取得 `deviceId`，校验有效权益和当前资源版本。
2. 在数据库事务外生成短时票据并写入 Redis。
3. 响应只返回该设备和当前场景允许的下载描述。
4. 票据签发和异常使用写入下载审计；票据过期不改变权益。

## 11. API 视图边界

- 公开 API：分类摘要、已发布壁纸摘要、封面访问、类型和可用能力，不包含内部状态、存储键和完整资源。
- 设备 API：只访问当前设备的权益、兑换结果和下载票据，设备 ID 不能由请求体指定数据范围。
- 管理 API：可编辑分类、壁纸和资源，可生成兑换码批次并查看掩码及使用统计；不返回历史完整码。
- 同一个数据库实体在不同接口使用独立请求与响应 DTO。公开配置、管理配置和内部安全字段分开。

## 12. 后续设计输入

数据库设计应把本文件中的实体、唯一键、外键、状态、审计和并发约束落到 Flyway 可执行结构。OpenAPI V1 应只暴露本文件定义的场景 DTO，并为分页、错误码、时间、字符串 ID、幂等键和设备会话建立统一规则。

## 1.1.0 Android 安装身份增补

WP-A03 按 [SEC-002](../05-安全与合规/SEC-002-Android安装身份协议.md) 使用 Keystore RSA 2048 安装公钥持钥证明，挑战新增 RSA_SHA256。注册证据为签名时间/nonce/proof，同密钥新证明恢复同一 ACTIVE credential，禁用/撤销拒绝；不证明物理设备唯一性或 APK 来源。清数据/卸载丢失密钥后无自动权益迁移。Android evidence_hash 为 HMAC(scope + 公钥 DER 指纹)，公钥写入已有 public_key_pem，secret_hash 为空。

数据库结构无变化，Flyway V1 字节保持；不创建无必要 V2。H5 HMAC 流程兼容，消费者枚举兼容新增算法但 H5 仍拒绝非 HMAC。历史 1.0.1 快照保留，当前 1.1.0 审核快照记录本次字段语义与 DTO 变更，验收结果见 WP-A03。

## 1.2.0 安全资源交付增补

新增安装解密公钥绑定（device_encryption_key）与不可变安全资源包（secure_resource_package）。签名凭据仍决定权益身份，独立 RSA 解密公钥只用于内容密钥包装，不替换原 credentialKeyId。资源版本先 READY→制作 format 2 安全包→发布；已有包不重建，已发布无包的历史版本需新增版本。公开展示和安全包可用性是不同事实；H5 占位描述保持。

安全包受益设备、资源版本、包摘要由 MySQL 事实约束；Redis 90 秒票据可丢失，不能形成或恢复权益。撤销权益/凭据、设备禁用、作品下架和版本退役均使旧票据不能开始新的读取。已开始的流允许完成，已下载内容不能远程收回。客户端还须完成 A06 的摘要/签名/安全安装，不把服务端交付通过当作系统设置通过。

Android 首次兑换要求存在已发布且有安全包的 Android/UNIVERSAL 兼容版本；不满足时 WALLPAPER_UNAVAILABLE，不扣额度、不创建新权益。旧权益与 H5 占位行为保留；已拥有时仍返回 ALREADY_OWNED，下载阶段再次判断可交付性。

## 1.3.0 App 内受限试用增补

新增 PreviewResourcePackage 资源派生事实，与正式 SecureResourcePackage 分表保存，不是试用权益。未获得者可使用带标记、受限规格的静态/视频/4D 资源在 App 内试用 120 秒；不扣额度、不创建设备权益、不设置系统壁纸。MySQL 保存派生包元数据，Redis 只保存独立 90 秒下载票据，120 秒交互状态仅保存在 Android 临时库和单调时钟截止记录。格式、加密 AAD、票据命名空间及客户端库相互隔离，见 [SEC-004](../05-安全与合规/SEC-004-Android受限试用交付协议.md)。

新 READY 版本成对制作正式包与派生包，失败共同回滚；已发布且已有正式包的历史版本允许补建派生包，禁止改变正式包、正式 manifest 与既有权益。已发布无正式包的历史版本继续要求新建版本。既有 H5 占位发布和兑换行为保留，不把派生包存在作为权益授权依据。
