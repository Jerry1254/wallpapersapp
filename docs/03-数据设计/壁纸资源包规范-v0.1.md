# 壁纸资源包规范 v0.1

**状态：** 草案
**格式版本：** 1
**创建日期：** 2026-09-10

## 1. 文件形式

资源包扩展名使用 `.4dwp`，文件内容为标准 ZIP。Android 系统不直接识别该扩展名，由本项目客户端负责下载、验证和解析。

```text
<wallpaper-id>.4dwp
├── manifest.json
├── cover.webp
└── layers/
    ├── background.webp
    ├── middle.webp
    ├── subject.webp
    └── foreground.webp
```

资源包内只允许 JSON、JPG、PNG 和 WebP，不允许包含可执行代码、动态链接库、HTML 或脚本。

## 2. manifest 示例

```json
{
  "formatVersion": 1,
  "wallpaperId": "city-hero-001",
  "version": 1,
  "canvas": {
    "width": 2048,
    "height": 2048
  },
  "sensor": {
    "maxAngle": 10,
    "smoothing": 0.2,
    "strength": 1.0
  },
  "layers": [
    {
      "file": "layers/background.webp",
      "depth": 0.0,
      "scale": 1.16,
      "opacity": 1.0,
      "blendMode": "normal"
    },
    {
      "file": "layers/subject.webp",
      "depth": 0.65,
      "scale": 1.16,
      "opacity": 1.0,
      "blendMode": "normal"
    }
  ]
}
```

## 3. 字段规则

| 字段 | 类型 | 规则 |
|---|---|---|
| `formatVersion` | 整数 | 必须为客户端支持的格式版本，v0.1 固定为 1 |
| `wallpaperId` | 字符串 | 1～64 位，仅允许小写字母、数字和连字符 |
| `version` | 整数 | 从 1 开始递增，同一 ID 不允许回退 |
| `canvas.width/height` | 整数 | 512～4096，所有图层必须采用相同画布 |
| `sensor.maxAngle` | 数字 | 5～25 度 |
| `sensor.smoothing` | 数字 | 0.05～0.5，数值越大越跟手 |
| `sensor.strength` | 数字 | 0～2 |
| `layers` | 数组 | 2～12 层，按从远到近排列 |
| `layer.file` | 字符串 | 必须位于资源包内部，禁止绝对路径和 `..` |
| `layer.depth` | 数字 | 0～1，越大越靠近观察者 |
| `layer.scale` | 数字 | 1～1.5，需留出位移安全边缘 |
| `layer.opacity` | 数字 | 0～1 |
| `layer.blendMode` | 枚举 | `normal`、`screen`、`add` |

## 4. 发布清单数据

公开列表和详情接口只返回展示信息，不返回永久资源地址：

```json
{
  "id": "city-hero-001",
  "name": "城市英雄",
  "coverUrl": "https://cdn.example.com/covers/city-hero-001.webp",
  "packageSize": 4281536,
  "version": 1,
  "resourceType": "layer_parallax",
  "entitled": true
}
```

只有设备已经获得该壁纸时，客户端才能向下载授权接口申请短时票据。票据响应包含短时签名地址、密文摘要、明文摘要、失效时间和按当前安装公钥包装的内容密钥。票据有效期为 60 至 120 秒，不得缓存为永久地址。

对象存储保存 AES-GCM 加密后的资源包。客户端在 App 私有目录解密和安装；公开 API、日志和埋点不得出现对象 Key、内容密钥或永久下载地址。

## 5. 下载和安装规则

1. 客户端先用设备会话和壁纸权益申请短时下载票据。
2. 下载密文到以 `.part` 结尾的 App 私有临时文件。
3. 校验密文长度和 SHA-256，再使用平台安全存储中的安装私钥解开内容密钥。
4. 使用 AES-GCM 解密，并校验明文 SHA-256 和 manifest 签名。
5. 解压到临时目录，限制文件数量、单文件大小和解压后总大小。
6. 拒绝绝对路径、软链接和包含 `..` 的路径。
7. 校验 manifest、图片类型、画布尺寸和 Alpha 通道需求。
8. 全部通过后，将临时目录原子重命名为 `<wallpaper-id>/<version>`。
9. 最后更新 `current.json`，避免壁纸服务读取到半成品。
10. 任何一步失败都删除本次临时文件，并记录不含密钥和地址的安全事件。

## 6. 兼容策略

- 客户端遇到更高的 `formatVersion` 时停止安装并提示升级应用。
- 同一格式版本只能增加可选字段，不能删除字段或改变既有含义。
- 不兼容的渲染能力通过提升 `formatVersion` 发布。
- 服务端保留仍被受支持客户端使用的旧版本资源包。
