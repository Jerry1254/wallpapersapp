# API-003 兑换、设备与权益 API 实现说明

**状态：** 已实现

**日期：** 2026-09-11

**契约：** `contracts/openapi/openapi.yaml` V1.0.0

## 1. 实现范围

WP-P08 实现冻结契约中的 18 个设备、交付和管理查询操作：

- H5 联调设备注册、一次性挑战和短期设备会话。
- 当前设备权益列表、幂等兑换、兑换结果恢复和下载描述。
- 兑换码批次生成、短时一次性交付、交付确认、批次与掩码额度查询。
- 管理端兑换事实列表/详情和匿名设备列表/详情。
- 管理后台兑换码、兑换记录和设备权益三个页面的真实 HTTP Repository。

公开目录的 4 个读取操作属于 WP-P09。H5 兑换页面与权益页面接入属于 WP-P10。

## 2. 设备身份与签名

基础配置要求提供 32 字节十六进制 `QJ_SECURITY_MASTER_KEY`。服务端按用途派生独立 HMAC/AES 密钥，不把主密钥、设备 secret、会话 token 或签名材料写入数据库和日志。

本阶段设备 Provider 有明确环境边界：

- `local` 只允许 `H5_TEST + H5_TEST_SECRET + h5-local`。
- `test` 只允许 `H5_TEST + H5_TEST_SECRET + h5-integration`。
- 默认配置关闭 H5 测试 Provider；非 H5 平台凭据在正式 App Provider 落地前返回稳定拒绝。

H5 注册响应只返回一次派生 secret，数据库仅保存带用途的 keyed hash。重新提交相同环境证据会关联原匿名设备、撤销旧 H5 凭证并轮换新凭证。

挑战保存于 Redis，并通过原子 get-and-delete 保证只能使用一次。会话 proof 和敏感写请求签名均按 API-001 的 UTF-8 规范计算；敏感请求另外校验时间偏差、UUID nonce、原始请求体 SHA-256 和规范化路径。nonce 在 Redis 中短时占位，重复签名请求返回冲突。

## 3. 兑换码批次与一次性交付

兑换码使用安全随机源生成 20 位字符。MySQL 中只保存：

- 带用途与版本的 HMAC-SHA-256；
- 用于客服核对的末五位；
- 总额度、已用额度和锁版本。

创建批次需要 UUID `Idempotency-Key`。服务端由管理员主体和幂等键确定批次号，同键同参数不会生成第二批码，同键异参返回 `IDEMPOTENCY_KEY_REUSED`。并发同键使用 READ COMMITTED 与批次号唯一约束收敛到同一批次。

完整码只进入 AES-GCM 加密的 Redis 短时材料，默认保留 10 分钟；数据库、管理列表和审计不保存完整码。交付票据以 SHA-256 形式作为 Redis key，下载响应为 CSV。管理端在浏览器开始保存 CSV 后调用交付确认，服务端立即删除短时明文材料。确认或过期后不能从数据库恢复完整码。

## 4. 兑换事务与权益

兑换以 MySQL 为业务事实源，在单事务内完成：

1. 锁定匿名设备，串行化同设备写入。
2. 按设备和幂等键读取或创建 `redemption_request`。
3. 已拥有该壁纸时记录 `ALREADY_OWNED`，额度变化为 0。
4. 锁定兑换码行并检查额度。
5. 条件递增 `used_quota`，创建唯一设备权益。
6. 创建不可重复的 `redemption_event`，完成幂等请求。

缺失兑换码、额度耗尽和已下架壁纸都会形成可查询的最终业务结果。相同设备、相同幂等键和相同请求返回原结果；异参返回 409。Redis 会话或限流数据清空后，已完成兑换结果仍可从 MySQL 恢复。

事务不会对不存在的幂等行做 `FOR UPDATE` 范围锁。相同设备由设备行锁保护，不同设备只在兑换码行上按固定顺序竞争，从而避免空唯一索引的 InnoDB gap lock 死锁，并保证并发额度不超发。

## 5. 权益、下载与管理查询

`GET /device/me/entitlements` 只返回当前会话设备的 ACTIVE 权益和公开壁纸视图。H5 联调请求下载时先校验设备、平台与作品授权：`FREE` 免权益，`REDEEM` 要求有效权益，然后返回 `H5_PLACEHOLDER` 描述。

正式 App 的平台安装公钥证明、内容密钥包装、加密资源包和 `/delivery/files` 有效票据属于后续 App 安全交付阶段。在此之前服务端不会降级签发永久资源地址。

管理查询只返回设备 ID、平台、安装范围、状态、凭证标识/类型/状态、壁纸权益和业务时间。响应不包含设备 secret/hash、证据 hash、公钥正文、完整兑换码、存储键或文件系统路径。

管理端支持：

- 批次生成、一次性 CSV 下载、交付确认、批次汇总和掩码额度查询；
- 按末位码、壁纸、设备、结果和时间查询兑换事实；
- 按平台和状态查询匿名设备，并查看凭证活动与权益。

## 6. 限流与错误

注册、挑战、会话、设备读、敏感写、兑换设备、兑换码摘要、下载票据和批次生成均使用用途隔离的 Redis 计数 key。主体材料先做 SHA-256，再组成 Redis key。超过窗口限制返回 429 `RATE_LIMITED` 和 `Retry-After`。

稳定错误码覆盖会话过期、凭证撤销、签名无效、nonce 重用、幂等键异参、兑换码无效/耗尽、权益缺失、交付票据无效和交付材料过期。业务拒绝的兑换响应仍使用冻结契约中的 `RedemptionResult`。

## 9. 1.8.0 免费作品授权增补

作品级 `accessType` 只允许 `REDEEM/FREE`。免费作品申请 H5 或 Android 正式下载票据时不要求权益，但仍执行设备会话、请求签名、平台、发布状态、兼容资源、安全包与限流校验；需兑换作品保持 `ENTITLEMENT_REQUIRED`。票据记录签发时的授权类型，因此免费改回需兑换只影响新票据，已签发免费票据仍受原 90 秒有效期和作品/凭据/版本状态约束。

免费作品的误兑换保存 `WALLPAPER_FREE` 最终结果，`quotaDelta=0`、`codeId=null`、`entitlementId=null`。幂等重试返回同一结果，管理查询可以按该结果筛选。
