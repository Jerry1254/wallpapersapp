# API-005 H5 设备、兑换与权益联调说明

**工作包：** WP-P10

**状态：** 已实现

**范围：** 本地 H5_TEST 设备身份、签名兑换、结果确认、权益列表与下载占位描述；沿用 OpenAPI V1，无契约变更。

## 1. 设备身份

H5DeviceProvider 仅使用 H5_TEST / H5_TEST_SECRET / h5-local。首次访问权益或需要兑换时创建随机 evidenceToken，先保存证据，再调用设备注册接口；同一浏览器保留站点数据时重用凭据。凭据保存在 qingjing-h5-test-device-v1，会话只留在内存，刷新后重新完成 challenge/proof。

证明使用 Web Crypto 的 UTF-8 HMAC SHA-256 和无填充 Base64URL。会话规范串为 QJ-DEVICE-SESSION-V1、credentialKeyId、challengeId、nonce 和 Java Instant 格式时间戳，各段以换行分隔；毫秒为零时省略 .000。敏感请求按 QJ-SIGNED-REQUEST-V1、POST、完整 /api/v1 路径、时间戳、UUID nonce 和精确请求体 SHA-256 签名。

Redis 会话丢失或过期时只自动续会话一次；重试保留原请求体和 Idempotency-Key，重新签名并生成 nonce。本地测试凭据已被撤销且 challenge 返回 CREDENTIAL_NOT_FOUND 时，使用原 evidenceToken 重新注册，不创建新的浏览器证据。清除站点数据、更换浏览器或来源地址会创建另一测试设备，不能承诺正式设备恢复。Android/iOS/HarmonyOS 需要独立 Provider，本实现不替代平台私钥与设备证明。

## 2. 兑换和不确定结果

兑换码去除空白与连字符并转大写，验证为 20 位字母或数字。提交前保存 qj-pending-v1，内容仅为 key、wallpaperId 和规范请求体 hash，不保存明文码或请求体。200/201 及 422 业务结果共用 RedemptionResult；202 PROCESSING 保留待确认状态。

超时、网络失败、冲突或服务错误不会生成新兑换意图。用户可以 GET 原请求结果；刷新页面仍显示确认入口。确认返回 404 时允许继续查询，或重新输入原码、校验同一 bodyHash 后用原 key 重试。待确认期间更改壁纸或兑换码被拦截。400/401/403/404/429 等进入事务前的确定拒绝可结束当前请求；最终 GRANTED、ALREADY_OWNED 或业务拒绝清除待确认记录。界面只有服务端返回的权益可进入已获得状态。

## 3. 我的、详情与下载

useDeviceStore 按服务端分页同步权益，加载更多失败保留此前页并重试原页。详情会继续查询后续页，避免把第一页未出现的已获得壁纸误判为未获得。刷新成功会替换旧权益；原型 localStorage 中的 ownedIds 和预置壁纸已不再作为事实。

公开详情下线返回 404 时，可回退到真实权益内的壁纸摘要。公开封面下线返回 404 时列表和大图显示封面不可用。重复准备或设置演示前调用 download-tickets 核验权益。H5 只接受 H5_PLACEHOLDER，明确说明未下载正式资源、未修改系统壁纸；本地只保存演示完成和设置目标，不能产生权益。4D 姿态、动态视频、系统权限与设置继续占位。

## 4. 验证入口

在 apps/h5-prototype 执行 npm run check 和 npm run build。测试覆盖独立密码学向量、Java 时间戳、并发会话复用、刷新复用身份、401 有限续期、原体原 key 新 nonce、不确定兑换恢复、原码校验和服务端权益分页。浏览器与后台同一 MySQL 事实的证据见 WP-P10 验收记录；整栈重启与多设备额度竞争继续在 WP-P11 执行。
