# API-007 4D 固定资源包导入接口

**日期：** 2026-09-16
**状态：** 已按 [API-008](API-008-4D配置透传与管理后台改造方案.md) 升级为 v2 原始配置透传；OpenAPI 1.6.0。

## 1. 接口

管理后台继续使用以下两个端点：

- `POST /api/v1/admin/parallax-packages`：上传并校验 Web 模拟器导出的完整 ZIP。
- `POST /api/v1/admin/variants/{variantId}/parallax-resource-versions`：把已导入源包绑定成不可变资源版本。

身份、CSRF、审计、SHA-256 去重、60 秒上传超时和 15 秒普通请求超时保持不变。

## 2. ZIP 结构

```text
wallpaper.zip
├── cover.jpg
├── config.json
└── layers/
    ├── 01.png
    ├── 02.png
    └── NN.jpg
```

- 图层为 2～12 层，从 `01` 连续编号；`01` 是最前景，最后一层是完整不透明背景。
- 前景必须保留透明通道；所有图层尺寸必须与 `canvas.width/height` 一致。
- ZIP 路径、CRC、压缩格式、条目数和展开字节限制沿用既有安全检查。
- `config.json` 必须是无 BOM、无重复键、无尾随内容的 UTF-8 JSON，最大 64 KiB。

## 3. v2 配置边界

当前导入和正式发布只接受 `formatVersion=2`。API 在导入时只读取：

- `formatVersion`
- `canvas.width/height`
- `layers[].index`

API 不解释或转换 `motion`、各轴运动与初始位置、`direction`、`scale`、`opacity`、`blendMode` 等算法字段。上传 ZIP 中的 `config.json` 原始字节直接保存为 `PARALLAX_CONFIG`，正式签名包继续使用同一字节序列。

源图层与资源角色固定映射：`01…N-1` 对应 `FOREGROUND:0…N-2`，最后一层对应 `BACKGROUND:0`。该映射只用于在签名清单中定位文件，不改变配置内容或绘制算法。

导入允许 API 不认识的算法字段通过，以验证透传边界；当前 v2 Android 使用严格字段集合，因此正式包构建会拒绝带未知字段的 v2 配置。后续新增算法字段时先升级 `formatVersion` 并完成 Android、模拟器支持，再让 API 识别并放行新版本。

完整配置示例和 Schema 见 [4D 源包制作说明](../../packages/wallpaper-format/4D源包制作说明.md) 与 [`parallax-source-v2.schema.json`](../../packages/wallpaper-format/parallax-source-v2.schema.json)。

## 4. 导入响应

```json
{
  "id": "90",
  "originalFilename": "wallpaper-4d.zip",
  "mimeType": "application/zip",
  "sizeBytes": 23891234,
  "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "validationStatus": "READY",
  "cover": { "id": "901", "originalFilename": "cover.jpg", "mimeType": "image/jpeg" },
  "configFormatVersion": 2,
  "canvas": { "width": 1080, "height": 2160 },
  "layers": [
    { "index": 1, "originalFilename": "layers/01.png", "role": "FOREGROUND", "ordinal": 0 },
    { "index": 2, "originalFilename": "layers/02.png", "role": "FOREGROUND", "ordinal": 1 },
    { "index": 3, "originalFilename": "layers/03.jpg", "role": "BACKGROUND", "ordinal": 0 }
  ]
}
```

响应不展开算法字段，不返回源 ZIP 地址或内部存储路径。

## 5. 数据与发布

Flyway V6 清理尚未上线的 v1 测试数据和旧算法列，不修改已提交的 V5。`parallax_source_layer` 只保留图层编号、资产、文件名、角色和序号；`parallax_source_package.config_asset_id` 指向模拟器原始配置。

正式包生成时再次检查 v2 版本、稳定结构和当前 Android 支持的字段集合。算法参数的类型、范围和效果仍由模拟器生成、Android 执行，API 不复制算法校验。受限预览可以因缩放图层而改写 `canvas.width/height`，其余配置语义保持不变。

## 6. 验收

- 2、3、12 层 v2 示例均可导入、绑定、打包和发布。
- v1、图层跳号、尺寸错误、透明通道错误、路径穿越和损坏 ZIP 被拒绝。
- 未知算法字段可完成导入与原始字节保存，但不能生成正式包。
- 正式包中的 `PARALLAX_CONFIG` 与源 ZIP `config.json` SHA-256 相同。
- 管理后台只展示包名、大小、SHA-256、层数、画布和配置版本，不提供动画参数编辑。
