# API-008 4D 配置透传与管理后台改造方案

**日期：** 2026-09-15

**状态：** 已完成

**目标：** 4D 算法参数由 Web 模拟器与 App 共同约定，API 不参与效果计算。

## 1. 系统边界

| 模块 | 职责 |
|---|---|
| Web 模拟器 | 编辑、预览并导出完整 `config.json` |
| Android App | 只解析当前 `formatVersion=2` 配置，读取传感器并执行动画 |
| API | ZIP 上传安全、文件存储、版本绑定、签名加密与下发 |
| 管理后台 | 选择 ZIP、展示文件级解析结果、保存/发布 |

API 不解析、计算、重写或存储单独的 `offsetXPercent/offsetYPercent`、`initialOffsetXPercent/initialOffsetYPercent`、`direction`、`maxAngleX/maxAngleY` 及后续新增算法参数。配置参数变化不应再要求 API 发版。

## 2. API 保留的检查

`POST /admin/parallax-packages` 路径、请求形式和后续资源版本绑定端点保持不变。API 只做文件和上传安全检查：

- ZIP 可完整解压，CRC 正确，不允许路径穿越、符号链接、加密 ZIP、ZIP64、重复路径或未知文件。
- 根目录存在 `cover.jpg`、`config.json`和 `layers/`；图层文件从 `01` 连续编号，数量为 2～12。
- 封面和图层是可解码的支持图片，图层尺寸一致，前景保留透明通道，最后一层背景完全不透明。
- `config.json` 是不超过 64 KiB 的 UTF-8 JSON，没有 BOM、重复键或追加内容。API 只读取稳定结构字段 `formatVersion`、`canvas.width/height` 和 `layers[].index`。
- `canvas.width/height` 与每张图层像素尺寸一致，`layers[].index` 从 1 开始连续且数量与图层文件一致。
- 继续执行总字节、单文件字节、条目数、请求限流和失败回滚限制。

导入和正式包构建均不校验效果好坏、方向与强度、参数范围、图层运动关系或算法字段集合。`offsetXPercent/offsetYPercent`、`initialOffsetXPercent/initialOffsetYPercent`、`direction`、`scale`、`opacity`、`blendMode`、`maxAngleX/maxAngleY` 以及以后新增的算法字段都作为不透明 JSON 保存。当前只允许 `formatVersion=2`，其他版本明确失败；同一格式版本内增加或调整算法字段不要求 API 发版。只有配置语义不兼容并升级 `formatVersion` 时，API 才增加新版本及其稳定结构识别。Java 核对项见 [API-009](API-009-4D独立轴配置Java交接说明.md)。

## 3. 原样传递规则

1. 导入时将 ZIP 内的 `config.json` 原始字节保存为 `PARALLAX_CONFIG` 资产。
2. 不再生成另一份「Android 内部配置」，不调整字段顺序，不把源字段转换为 `role/ordinal/depth`。
3. 正式签名包放入这份原始配置。签名 manifest 继续记录每个文件的 role、ordinal、MIME、长度和 SHA-256，保证传输完整性。
4. 总图层数为 N 时，`01…N-1` 映射为 `FOREGROUND:0…N-2`，`NN` 映射为 `BACKGROUND:0`。这是包文件定位，不是效果计算。
5. 正式包中的 `PARALLAX_CONFIG` 必须与上传 ZIP 内 `config.json` 字节完全一致，SHA-256 相同。
6. 受限预览可生成降分辨率、带水印的派生图层。如图层尺寸变化，必须同步改写 `canvas.width/height`，因此预览配置的字节和 SHA-256 会变化；除画布尺寸外的算法字段语义必须保持不变。

## 4. 数据库改造

V5 导入时会把源配置转换成 Android 内部配置后再写入 `config_asset_id`，因此现有测试记录不能视为原始配置。当前尚未上线，这些 v1 测试数据与资源直接清理，不迁移、不重打包、不提供运行时兼容。

新增 **V6 增量迁移**，不修改已提交的 V5。使用 V6 是为了维持 Flyway 迁移历史完整，不代表产品要兼容旧数据。V6 之后，新导入的 `parallax_source_package.config_asset_id` 指向上传 ZIP 中的原始 `config.json`，并作为配置唯一事实来源。

`parallax_source_layer` 只保留包结构和资产关系所需字段：

```text
source_package_id
layer_index
asset_id
original_filename
role
ordinal
```

V6 删除或停用 `depth/scale/opacity/blend_mode` 等旧算法列，新导入不再写入这些字段；不新增 `offset_percent` 列，避免以后每次算法参数改变都迁移数据库。

## 5. OpenAPI 与管理后台

`AdminParallaxSourceLayer` 不再返回算法字段，改为：

```json
{
  "index": 1,
  "originalFilename": "layers/01.png",
  "role": "FOREGROUND",
  "ordinal": 0
}
```

`AdminParallaxSourcePackage` 可增加只读的 `configFormatVersion`，但不展开配置内部字段。管理后台页面调整：

- 将「服务端自动解析封面、图层和景深配置」改为「上传模拟器导出的完整 ZIP」。
- 只展示包名、SHA-256、文件大小、图层数、图层尺寸和配置格式版本。
- 不展示、不编辑 4D 运动、初始位置、方向或其他动画参数；运营人员如需调整，返回 Web 模拟器重新导出完整 ZIP。
- 更新三层模板和配置下载文件为 `formatVersion=2`。

不新增端点，不改上传 60 秒与其他请求 15 秒的现有超时约定。

## 6. 实施验收

1. 上传一个带 API 未知新算法参数的 v2 ZIP，导入、原始字节保存和正式包构建均成功，证明 API 未绑定算法字段集合。
2. 下载正式安全包后，`PARALLAX_CONFIG` 与上传 ZIP 中 `config.json` 的 SHA-256 一致。
3. 路径穿越、损坏 ZIP、图层缺失/跳号、超限文件仍被拒绝。
4. 管理后台可上传、替换和发布 v2 ZIP，页面没有景深或位移参数编辑器。
5. v1 源包和旧 Android 内部配置被拒绝，新模板、测试样例和运行时只使用 v2。
6. 清理现有 v1 测试数据后，V6 数据库、API 和管理后台可用同一个 v2 ZIP 完成导入、发布和下发。
