# API-010 1.0 原资源详情预览 Java 交接说明

**日期：** 2026-09-16

**产品决定：** 1.0 以真实效果验证为主。Android App 详情页的静态壁纸、动态视频壁纸和 4D 动态壁纸均使用后台上传并发布的原始资源，不制作降清晰度、加水印或转码后的预览媒体。用户量和资源价值验证后，再单独规划预览资源保护。

## 1. 目标行为

| 资源类型 | 详情页预览资源 | 1.0 要求 |
|---|---|---|
| `STATIC_IMAGE` | 正式版本绑定的高清静态原图 | 原始文件字节，不使用列表封面 |
| `VIDEO` | 正式版本绑定的 MP4 | 原始 MP4 字节、原帧率、原分辨率、原时长 |
| `LAYER_PARALLAX` | 全部前景层、背景层和 `PARALLAX_CONFIG` | 所有文件保持原始字节，执行完整真实交互效果 |

这里的“原资源”指正式资源版本所绑定的 payload，不是 `cover.jpg`，也不是服务端生成的派生预览文件。

## 2. 保持不变的交付边界

详情页继续使用现有预览交付链路：

```text
POST /device/wallpapers/{wallpaperId}/preview-tickets
→ GET /preview/files
→ APP_PREVIEW 加密包
→ Android 预览专用存储与渲染器
```

以下安全和接口约束保持不变：

- `PreviewDescriptor.deliveryMode` 与 `purpose` 继续为 `APP_PREVIEW`。
- 预览包外壳继续使用 format 3、独立 AAD、签名和设备公钥包装内容密钥，不能作为正式 format 2 包安装。
- 预览下载继续使用 90 秒短期票据、`Cache-Control: no-store`、设备会话、签名请求、限流和用途隔离。
- 作品下架、设备禁用、平台与系统版本兼容检查继续生效。
- 正式下载仍要求权益；预览接口仍不授予权益，也不返回正式下载票据。
- 接口地址、请求体、响应 DTO、OpenAPI Schema、数据库表结构和管理后台操作均不改变。

本次只改变 APP_PREVIEW 加密包内部的媒体来源。

## 3. Java 修改点

当前入口：

```text
SecurePackagePublisher.buildPreview(...)
└─ PreviewMediaReducer.reduce(type, source, dimensions)
   └─ 缩放、压缩、加水印、视频转码、4D 画布改写
```

1.0 改为：

```text
SecurePackagePublisher.buildPreview(...)
└─ SecurePackageCodec.encodePreview(identity, source, ...)
```

具体要求：

1. `buildPreview` 使用已经过正式资源校验的 `source` payload 列表直接制作预览包。
2. 不再通过 `PreviewMediaReducer.reduce()` 生成详情页预览 payload。
3. `STATIC_IMAGE` 的预览 payload 与正式包中的 `STATIC_IMAGE` 内容字节和 SHA-256 一致。
4. `VIDEO` 的预览 payload 与正式包中的 `VIDEO` 内容字节和 SHA-256 一致；禁止改帧率、裁切、限时、压缩、加水印或重新编码。
5. `LAYER_PARALLAX` 的全部 `FOREGROUND`、`BACKGROUND` 和 `PARALLAX_CONFIG` 与正式包对应 payload 字节和 SHA-256 一致；禁止改写 `canvas.width/height` 或算法字段。
6. APP_PREVIEW 包的 manifest、签名、随机内容密钥、密文和整体 SHA 与正式包不同是正常行为；验收比对的是每个 payload 的内容 SHA。
7. `PreviewMediaReducer` 如果暂时没有其他调用方，可以保留未调用，待 1.0 稳定后再删除；不要为了本次调整扩大改动范围。

## 4. 既有预览包处理

当前 `SecurePackagePublisher.buildLocked` 在正式包和预览包都已存在时会直接返回，因此代码修改不会自动替换已经生成的派生预览包。

产品尚未上线，处理方式如下：

1. 保留正式 `secure_resource_package`，不重建正式资源版本。
2. 清理测试环境现有 `preview_resource_package` 记录及其对应存储对象。
3. 对现有 READY/PUBLISHED 测试版本重新执行安全包制作，使 API 只补建新的原资源 APP_PREVIEW 包。
4. 清理通过受控维护脚本或现有存储 Adapter 完成，数据库记录与对象存储同步删除，避免孤儿文件。

本次没有数据库结构变化，不新增 Flyway 表或字段。是否用一次测试数据清理迁移或维护脚本，由 Java 根据当前测试环境部署方式决定。

## 5. App 配合范围

- 动态视频和 4D 详情页已经请求 APP_PREVIEW 包，并使用与正式资源相同的原生播放器/4D 渲染器。API 换成原 payload 后，无需修改这两类详情页逻辑。
- 静态详情页当前直接展示目录封面，没有请求 APP_PREVIEW 包。API 已支持 `STATIC_IMAGE` 预览票据，但 App 仍需把静态详情主图接到预览包中的原始 `STATIC_IMAGE`；这部分属于 App 修改，不由 Java 通过公开原图 URL 规避。
- H5 继续使用公开封面，不在本次范围内公开静态原图、原始 MP4 或 4D 分层文件。

## 6. 验收标准

### 6.1 API 自动验证

分别制作静态、视频和 4D 测试版本，解密测试中的正式包与 APP_PREVIEW 包，逐项断言：

- 静态 `STATIC_IMAGE` payload SHA-256 完全一致。
- 视频 `VIDEO` payload SHA-256、字节数完全一致。
- 4D 每个 `FOREGROUND/BACKGROUND` payload 与 `PARALLAX_CONFIG` SHA-256 完全一致。
- APP_PREVIEW manifest 仍包含 `purpose=APP_PREVIEW`、`formatVersion=3`。
- APP_PREVIEW 包仍不能通过正式包 purpose/format 校验器安装。
- 无权益设备可以获取有效预览票据，但正式下载仍返回权益限制。
- 过期、错设备、错用途和下架资源的预览票据继续失败。

### 6.2 联调验证

- 静态详情页显示上传的高清原图，而不是列表封面。
- 视频详情页静音循环播放上传的原始 MP4，画质、帧率、构图和时长不被服务端改变。
- 4D 详情页使用原始图层、原始画布和原始参数，倾斜及触摸预览与正式设置后的效果一致。
- 已下载正式资源时，详情页继续切换到本地正式包，不发生重复下载或画面变化。

## 7. Java 交付结论

Java 需要修改预览包生成逻辑并重建现有测试预览包；不修改接口、数据库结构或管理后台。完成后把三类 payload SHA 对比测试结果交给 App 联调即可。
