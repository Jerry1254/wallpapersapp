# API-011 4D 真机调试配置保存实现说明

**日期：** 2026-09-16
**状态：** 实现完成，待真机验收

## 1. 接口

```http
POST /api/v1/admin/lab/wallpapers/{wallpaperId}/parallax-config
Cookie: QJ_ADMIN_SESSION=...
X-CSRF-Token: ...
Content-Type: application/json

{
  "baseResourceVersionId": "123",
  "config": { "formatVersion": 2, "canvas": {}, "motion": {}, "layers": [] }
}
```

成功返回 `201`：

```json
{
  "resourceVersionId": "124",
  "versionNo": 13,
  "configFormatVersion": 2
}
```

## 2. 保存语义

- 客户端只在用户确认后提交一次完整 `config`，拖动单个参数不请求 API。
- `baseResourceVersionId` 必须仍是该壁纸当前已发布的 Android 4D 版本；否则返回 `409 VERSION_CONFLICT`。
- API 比较稳定外壳：`formatVersion`、`canvas.width/height`、图层数量与图层索引必须与基础版本一致。
- API 不绑定运动算法 DTO，不计算或限制 `offsetXPercent`、`offsetYPercent`、初始位置等参数。
- 服务端复用原图层资产和顺序，只创建新配置资产、新资源版本和两种安全包（正式包与 APP_PREVIEW）。
- 新版本制作与发布全部成功后才替换当前版本；任一步失败整体回滚，旧版本仍保持已发布。
- 原图层、封面和已有版本不覆盖、不删除，可由管理后台回滚。

## 3. 权限与错误

| 场景 | 结果 |
|---|---|
| 未登录或会话失效 | `401` |
| CSRF 缺失或错误 | `403` |
| 基础版本已更新 | `409 VERSION_CONFLICT` |
| 画布、图层结构或 v2 格式不合法 | `422 CONFIG_INVALID` |
| 新安全包构建失败 | 请求失败并回滚，不切换版本 |

## 4. 客户端配合

- Lab App 使用独立应用 ID `com.qingjing.qingjing_wallpaper.lab`，与正式体验包可同时安装。
- 进入 4D 详情后使用 APP_PREVIEW 原图层完整渲染，参数变化直接送给已加载的原生渲染器，不重新解码图片。
- 未保存配置写入 App 私有草稿；基础版本不一致时不会套用旧草稿。
- 右上角是唯一保存入口，确认后整体保存；返回时可以保存并返回、放弃并返回或继续调整。
