# API-012 免费壁纸获取方式接口交接说明

**日期：** 2026-09-16

**状态：** 前端、Java、数据库、OpenAPI 与管理后台已实施，待业务验收

**对应任务：** PM-002 / WP-UI10

**管理后台交接：** [IXD-WP-ADMIN-003](../01-产品需求/IXD-WP-ADMIN-003-免费壁纸获取方式管理后台修改说明.md)

## 1. 目标与边界

API 增加作品级获取方式 `accessType`，只表达用户取得正式资源前是否需要兑换：

```yaml
WallpaperAccessType:
  type: string
  enum: [REDEEM, FREE]
```

- `REDEEM`：默认值，正式下载要求设备已经拥有该壁纸权益。
- `FREE`：不要求权益即可申请正式下载票据。
- 获取方式与分类、`WallpaperKind`、平台变体、资源版本、精选状态互相独立。
- 预览、安全包、票据、设备签名、限流和资源兼容校验保持现状。

API 不根据分类、标题、标签、下载次数或兑换记录推导获取方式。

## 2. 数据库

在 `wallpaper` 作品表新增非空字段：

```sql
access_type VARCHAR(16) NOT NULL DEFAULT 'REDEEM'
```

约束只允许 `REDEEM`、`FREE`。通过新的 Flyway 增量迁移增加字段和约束；当前尚未上线的测试数据统一为 `REDEEM`，不能因为空值变成免费。

`access_type` 不放在资源版本、平台变体、权益或兑换表中。修改它不生成资源版本，也不修改已有权益和兑换事件。

## 3. OpenAPI 与 DTO

### 3.1 管理端写入与读取

以下 Schema 增加必填 `accessType: WallpaperAccessType`：

- `WallpaperWriteRequest`
- `AdminWallpaperSummary`
- `AdminWallpaperDetail`（通过 Summary 继承）

`POST /admin/wallpapers` 未提供字段时返回 `400`；管理后台会始终提交。服务端领域模型仍设置 `REDEEM` 默认值，防止非 HTTP 导入路径意外创建免费作品。

`GET /admin/wallpapers` 增加可选查询参数：

```text
accessType=FREE | REDEEM
```

它可与 `status`、`kind`、`categoryId`、`q` 和分页组合。

### 3.2 公开目录

`PublicWallpaperSummary` 将 `accessType` 设为必填，因此列表、搜索、分类和详情响应都返回同一字段。示例：

```json
{
  "id": "123",
  "title": "城市飞行",
  "kind": "PARALLAX_4D",
  "accessType": "FREE"
}
```

`GET /public/wallpapers` 增加可选查询参数 `accessType`：

- 省略：不按获取方式过滤，继续执行现有精选、类型、分类和搜索规则。
- `FREE`：只返回已发布的免费作品，用于首页“免费壁纸”。
- `REDEEM`：只返回需兑换作品。
- 非法值：返回 `400`，不能当作省略处理。

排序沿用现有 `DEFAULT` / `NEWEST`，不增加“免费分类”或新的系统视图。

## 4. 正式下载授权

`POST /device/wallpapers/{wallpaperId}/download-tickets` 的业务授权改为：

```text
作品已发布且资源可交付
AND（wallpaper.accessType == FREE OR 当前设备存在有效权益）
```

两种路径后续完全共用：设备会话、请求签名、平台与系统版本匹配、安全包 READY 检查、限流、短时票据和加密包交付都不能绕过。

- `FREE` 不写入 `device_wallpaper_entitlement`，不创建兑换事件，不扣兑换码额度。
- `REDEEM` 没有权益时继续返回现有 `ENTITLEMENT_REQUIRED`。
- 免费作品下架后不能申请新票据；已安装资源不由服务端远程删除。
- H5 的 `H5_PLACEHOLDER` 和正式 App 的 `SECURE_PACKAGE` 都使用相同的免费授权判断。
- APP_PREVIEW 仍使用现有预览权限，不因免费状态改变 payload 或预览保护。

## 5. 兑换接口

`POST /device/redemptions` 收到免费作品时，不创建权益、不扣额度，并返回稳定业务结果。建议在现有 422 业务响应中增加：

```yaml
result: WALLPAPER_FREE
quotaDelta: 0
```

同时在 OpenAPI 枚举与前端错误文案中登记。这样旧客户端即使误开兑换面板，也不会浪费兑换码。幂等记录应保存该确定结果，重试仍为 `quotaDelta=0`。

新增结果还要同步更新 `redemption_event.result` 的数据库检查约束、Java 枚举、管理端兑换记录 DTO/标签/筛选和两端客户端结果枚举。不能只改 Controller 返回字符串，否则写入兑换事件时会被现有约束拒绝。

免费作品不自动出现在 `GET /device/me/entitlements`；“我的已获得”继续只展示真实权益。已有权益在作品改为免费或改回需兑换时均保留。

## 6. 缓存与状态变更

`accessType` 进入公开目录投影和管理端 DTO。当前目录读取直接查询 MySQL，没有列表或详情缓存，因此保存后下一次请求立即生效：

- `REDEEM → FREE` 后立即进入免费筛选，下载票据不再查权益。
- `FREE → REDEEM` 后立即退出免费筛选，下一次票据申请恢复权益校验。

已签发的短时票据内保存签发时的 `FREE` / `ENTITLEMENT` 授权类型，在原 90 秒有效期内按该授权继续使用；不为获取方式变更增加远程撤销机制。作品下架、凭据撤销、设备停用和资源版本退役仍会使票据失效。

## 7. 前后端兼容约定

前端当前只把严格的字符串 `FREE` 视为免费。`accessType` 缺失、为 `REDEEM` 或出现未知值时，都按需要兑换处理。这是防止旧 API 或异常数据意外放开正式资源的保护。

Java 实施完成后，公开与管理 DTO 必须始终返回字段；客户端的缺失回退不能替代服务端数据迁移和非空约束。新增获取方式时应先升级客户端语义，不能让旧客户端把未知值当作免费。

## 8. 自动测试与联调清单

### API / 数据库

1. Flyway 从当前库升级后所有旧行均为 `REDEEM`，字段非空且非法值失败。
2. 管理端新建、编辑、列表和详情完整读写 `accessType`，ETag 冲突规则不变。
3. 公开列表可按 `FREE` / `REDEEM` 过滤，并能与分类、类型、关键词、精选和分页组合。
4. 公开列表与详情始终返回 `accessType`。
5. 无权益设备可获得免费作品的 H5 与 App 下载票据；同设备不能下载需兑换作品。
6. 免费作品仍需通过发布状态、兼容性、安全包、签名、限流和票据校验。
7. 对免费作品兑换返回 `WALLPAPER_FREE`、`quotaDelta=0`，批次额度、权益和事件事实不增加。
8. 免费改回需兑换后，新票据恢复权益限制；原有权益仍有效。
9. 修改获取方式不新增资源版本，不改变原 payload、安全包或 4D 配置。

### 联调

1. 后台将一件 A 分类作品设为免费并发布，作品仍留在 A 分类，同时出现在首页“免费壁纸”。
2. 首页、分类和搜索卡片均显示“免费”。
3. 免费详情不请求权益列表、不弹兑换框，直接进入下载和设置。
4. 未返回新字段的旧本地 API 上，前端仍按需兑换，不会意外放开资源。

## 9. 实施结果

- Flyway V8 增加 `wallpaper.access_type` 非空列、受控约束和公开筛选索引，旧行统一为 `REDEEM`。
- 公开列表/详情、管理列表/详情/写入和两端筛选都已接入 `accessType`。
- H5 占位交付和 Android 安全包交付共用免费授权；签名、平台、安全包、状态与限流校验保留。
- 免费作品的误兑换保存 `WALLPAPER_FREE` 幂等结果，不扣额度、不建权益，管理端可展示和筛选。
- 管理后台已增加获取方式单选、列表标识与筛选；新建默认为需兑换。
