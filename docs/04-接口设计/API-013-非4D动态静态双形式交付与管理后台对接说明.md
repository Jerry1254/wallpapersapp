# API-013 非 4D 动态/静态双形式交付与管理后台对接说明（已废止）

**原版本：** 1.0.0

**状态：** 已废止，不得继续作为 App、Java API、数据库或管理后台的实施依据

**废止日期：** 2026-09-17

**替代方案：** [API-014 单商品多设置能力与设备能力协商全链路整改方案](API-014-单商品多设置能力与设备能力协商全链路整改方案.md)

## 1. 废止原因

原方案把 `STATIC`、`DYNAMIC`、`PARALLAX_4D` 视为互斥作品类型，并要求非 4D 动态作品强制同时发布 `UNIVERSAL / STATIC_IMAGE`。产品规则已经调整为：

1. 同一款壁纸商品可以同时拥有 Android 4D、Android 动态、iOS 动态、鸿蒙原生动态和通用静态中的任意一种或多种设置能力。
2. 展示封面只负责展示，不自动产生静态设置能力。
3. App 上报设备实际可用的设置能力；API 只返回与已发布商品能力存在交集的商品。
4. 早期鸿蒙可以复用 Android 壁纸资源，但不能使用鸿蒙原生动态资源；新鸿蒙原生系统使用鸿蒙原生资源；Android 容器能运行 APK 不代表能够调用宿主系统壁纸接口。
5. 动态桌面与动态锁屏是同一资源的不同设置位置，只要设备至少支持其中一个位置，该资源能力就可用。

因此，原方案中的强制静态资源、互斥 `kind`、按平台名称直接过滤和固定动态/静态二选一均不再成立。

## 2. 对现有实现的影响

- App 已实现的“非 4D 动态固定带静态、只在动态/静态之间二选一”需要改为读取当前设备的可用能力列表。
- 管理后台已实现的“壁纸类型三选一”和“非 4D 动态强制上传静态原图”需要改为设置能力多选。
- Java 不得按本文件原 1.0.0 规则放开 `DYNAMIC + UNIVERSAL / STATIC_IMAGE` 后结束实施。
- 数据库、OpenAPI、目录过滤、下载票据和设备资料必须一起按 API-014 整改。

原文件的历史内容可通过 Git 历史查看；从本次整改开始，唯一有效交接文件为 API-014。
