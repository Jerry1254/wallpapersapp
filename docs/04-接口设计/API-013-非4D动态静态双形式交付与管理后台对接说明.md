# API-013 非 4D 动态/静态双形式交付与管理后台对接说明

版本 1.0.0，2026-09-17，对应 WP-UI13。本文同时作为 Java API 和管理后台的实施交接，不再拆分两份文档。

## 1. 问题与最终规则

动态壁纸的用户可能只喜欢某一帧静态画面，不希望安装动态效果。因此，非 4D 动态作品必须同时具有动态原资源和高清静态原图；用户获得的是“作品权益”，可在动态和静态之间选择，不重复兑换。

| 壁纸类型 | 必传资源 | 封面来源 | 用户设置形式 |
|---|---|---|---|
| 静态壁纸 | 高清静态原图 | 静态原图 | 仅静态 |
| Android 动态 | MP4 动态原资源 + 高清静态原图 | 静态原图 | 动态或静态 |
| 华为/鸿蒙动态 | 平台动态资源包 + 高清静态原图 | 静态原图 | 动态或静态 |
| 苹果动态 | Live Photo 视频/照片资源 + 高清静态原图 | 静态原图 | 动态或静态 |
| 4D 壁纸 | 4D 分层 ZIP + ZIP 内独立封面 | 4D 独立封面 | 仅 4D |

非 4D 类型不再上传独立列表封面。管理后台只上传一张高清静态原图；同一个 `asset` 同时作为：

1. 首页、列表和详情的展示封面；
2. `UNIVERSAL / STATIC_IMAGE` 的正式静态壁纸资源；
3. 动态作品选择“静态壁纸”时的交付内容。

当前 1.0 允许公开展示直接读取该原图。将来如增加缩略图派生，也只能由服务端从这一份原图生成，管理员不重复上传。

## 2. 权益与下载语义

- `DeviceEntitlement` 继续只绑定 `deviceId + wallpaperId`，不绑定资源形式。
- `REDEEM` 作品只兑换一次，同一权益可申请该作品的动态包或静态包。
- `FREE` 作品的动态和静态形式都免权益下载，现有免费规则不变。
- 用户每次只选择一种形式，App 只为该形式申请票据并下载对应包，不预下载另一份资源。
- 切换形式不再次兑换；只会新增一次已有权益校验和资源票据申请。
- 已设置到系统的壁纸与“已获得权益”仍是两类事实；本需求不修改卸载/重装的客服找回边界。

## 3. 管理后台已改交互

### 3.1 非 4D 表单

管理后台已移除“列表封面”独立上传项。

- 静态壁纸：显示一个必填项“高清静态原图（封面 / 静态壁纸）”。
- 动态壁纸：先显示同一个静态原图必填项，再按已选平台显示 MP4、Live Photo 或鸿蒙资源包。
- 上传静态原图时 `purpose=STATIC_IMAGE`，不再另外上传 `WALLPAPER_COVER`。
- 创建/编辑非 4D 作品时，`coverAssetId` 直接使用该 `STATIC_IMAGE` asset ID。
- 同一 asset ID 再用于 `UNIVERSAL / STATIC_IMAGE` 资源版本的 `STATIC_IMAGE:0` binding，不产生第二份文件。

### 3.2 资源变体组合

| 作品类型 | `platform` | `resourceType` | 必要 binding |
|---|---|---|---|
| 静态 | `UNIVERSAL` | `STATIC_IMAGE` | `STATIC_IMAGE:0` |
| Android 动态 | `UNIVERSAL` | `STATIC_IMAGE` | `STATIC_IMAGE:0` |
| Android 动态 | `ANDROID` | `VIDEO` | `VIDEO:0` |
| 苹果动态 | `UNIVERSAL` | `STATIC_IMAGE` | `STATIC_IMAGE:0` |
| 苹果动态 | `IOS` | `LIVE_PHOTO` | `LIVE_PHOTO_IMAGE:0` + `LIVE_PHOTO_VIDEO:0` |
| 华为/鸿蒙动态 | `UNIVERSAL` | `STATIC_IMAGE` | `STATIC_IMAGE:0` |
| 华为/鸿蒙动态 | `HARMONYOS` | `THEME_PACKAGE` | `THEME_PACKAGE:0` |
| 4D | `ANDROID` | `LAYER_PARALLAX` | 按现有 4D ZIP 解析结果 |

动态作品不新增 `kind`，仍为 `DYNAMIC`。“可以设为静态”由公开详情中同时存在当前平台动态 capability 和 `UNIVERSAL / STATIC_IMAGE` capability 表达，不增加布尔字段。

## 4. Java API 需要修改的位置

### 4.1 数据库

现有 `wallpaper_variant`、`resource_version`、`resource_binding`、`secure_resource_package` 已能表达一个作品的多个平台/资源类型变体，**不需要新表、新列或 Flyway 迁移**。

项目未上线，不保留旧动态测试数据兼容。现有缺少 `STATIC_IMAGE` 变体的动态测试作品可直接删除后重新上传，不需要自动生成假静态图。

### 4.2 作品与变体校验

`AdminWallpaperService.validateVariantForKind(...)` 当前会拒绝 `DYNAMIC + UNIVERSAL + STATIC_IMAGE`，需改为允许以下精确组合：

```text
PARALLAX_4D -> ANDROID / LAYER_PARALLAX
STATIC      -> UNIVERSAL / STATIC_IMAGE
DYNAMIC     -> UNIVERSAL / STATIC_IMAGE
DYNAMIC     -> ANDROID / VIDEO
DYNAMIC     -> IOS / LIVE_PHOTO
DYNAMIC     -> HARMONYOS / THEME_PACKAGE
```

不要放宽成“任意非 UNIVERSAL 平台 + 任意动态类型”，否则会把 iOS Live Photo 误发给 Android。

`coverAssetId` 现有校验只要求 READY 图片，已能接受 `purpose=STATIC_IMAGE` 的 asset，无需改 DTO。

### 4.3 发布完整性校验

`publish(...)` 当前只要选中任意一个资源版本就可发布，需在发布事务内增加：

1. `STATIC` 必须且只需一个 `UNIVERSAL / STATIC_IMAGE` 已选版本。
2. `DYNAMIC` 必须选中一个 `UNIVERSAL / STATIC_IMAGE` 版本，且至少选中一个符合上表的动态版本。
3. `DYNAMIC` 的 `wallpaper.cover_asset_id` 必须等于当次选中的 `STATIC_IMAGE:0` binding asset ID。
4. `STATIC` 的 `wallpaper.cover_asset_id` 同样必须等于 `STATIC_IMAGE:0` binding asset ID。
5. `PARALLAX_4D` 保持现有 ZIP 内封面与分层包规则，不要强制绑定 `STATIC_IMAGE`。

发布失败使用现有 `DOMAIN_RULE_VIOLATION` 或 `RESOURCE_VERSION_NOT_READY`，详细 message 要能区分“缺静态原图”与“缺动态资源”。

### 4.4 公开目录

公开列表/详情 DTO 结构不变。一个 Android 动态作品的 `capabilities` 应同时返回：

```json
[
  {
    "platform": "ANDROID",
    "resourceType": "VIDEO",
    "minOsVersion": null,
    "capabilityRequirements": []
  },
  {
    "platform": "UNIVERSAL",
    "resourceType": "STATIC_IMAGE",
    "minOsVersion": null,
    "capabilityRequirements": []
  }
]
```

`cover` 仍使用现有 `PublicMedia`，但其 `assetId` 是静态原图 asset ID。

### 4.5 下载票据

`POST /device/wallpapers/{wallpaperId}/download-tickets` 的 Schema 不需要增字段。App 将用户选择转为只包含一项的 `supportedResourceTypes`：

选择动态：

```json
{
  "platform": "ANDROID",
  "osVersion": "13",
  "supportedResourceTypes": ["VIDEO"]
}
```

选择静态：

```json
{
  "platform": "ANDROID",
  "osVersion": "13",
  "supportedResourceTypes": ["STATIC_IMAGE"]
}
```

Java 必须精确返回请求类型的 `resourceVersion`。该类型不可用时返回 `SECURE_PACKAGE_NOT_READY`，不得自动换成另一种形式。现有 App 会校验返回的 `resourceVersion.resourceType` 必须与选择一致。

`DownloadTicketService` 的权益校验继续使用 `wallpaperId`，不对 `resourceType` 再建权益。`SecurePackagePublisher` 已支持 `STATIC_IMAGE`、`VIDEO` 和 `LAYER_PARALLAX`；Android 动态作品新增的静态变体沿用现有静态安全包制作。

### 4.6 OpenAPI

现有 `WallpaperKind`、`ResourceType`、`DeliveryCapability`、`CreateDownloadTicketRequest` 已能表达新规则，无需新 Schema。建议将契约版本升级到下一个小版本，并补充两处 description：

- `DYNAMIC` 可同时包含平台动态变体与 `UNIVERSAL / STATIC_IMAGE`。
- 一份作品权益授权该作品所有可交付形式，每次票据只选定一种资源类型。

## 5. 管理后台与 API 调用示例

Android 动态壁纸的建议调用顺序：

```text
1. POST /admin/assets
   purpose=STATIC_IMAGE, file=wallpaper.png
   -> staticAssetId=901

2. POST /admin/assets
   purpose=VIDEO, file=wallpaper.mp4
   -> videoAssetId=902

3. POST/PATCH /admin/wallpapers
   kind=DYNAMIC
   coverAssetId=901

4. POST /admin/wallpapers/{id}/variants
   platform=UNIVERSAL, resourceType=STATIC_IMAGE

5. POST /admin/variants/{staticVariantId}/resource-versions
   bindings=[{assetId:901, role:STATIC_IMAGE, ordinal:0}]

6. POST /admin/wallpapers/{id}/variants
   platform=ANDROID, resourceType=VIDEO

7. POST /admin/variants/{videoVariantId}/resource-versions
   bindings=[{assetId:902, role:VIDEO, ordinal:0}]

8. 分别制作 STATIC_IMAGE 和 VIDEO 安全包

9. POST /admin/wallpapers/{id}/publish
   resourceVersionIds=[staticVersionId, videoVersionId]
```

管理后台已按这个顺序组装；在 Java 完成 4.2 和 4.3 前，真实发布会在创建 `DYNAMIC + UNIVERSAL / STATIC_IMAGE` 变体时被现有 API 拒绝。

## 6. App 已实施行为

- 公开详情同时出现平台动态 capability 和 `STATIC_IMAGE` capability 时，点击主按钮后弹出“选择设置方式”。
- 选项为“动态壁纸”和“静态壁纸”，动态优先用于详情效果预览。
- 未获得的 `REDEEM` 作品先完成一次兑换，再选择资源形式。
- 每种形式独立检查本机已安装版本；已安装就直接进入系统设置，未安装只下载当前选中形式。
- 静态作品和 4D 作品只有一种形式，不显示选择弹层。
- 正式 App 和 4D Lab 共用该详情/下载逻辑；Lab 只在 4D 详情调参页与正式 App 分流。

## 7. 验收用例

1. 新建静态作品时只出现一个静态原图上传框；上传请求只有一次，`coverAssetId` 与 `STATIC_IMAGE:0` 的 asset ID 相同。
2. 新建 Android 动态作品时静态原图和 MP4 都是必填；缺任一项不得发布。
3. 新建 iOS 或华为/鸿蒙动态作品时，同样必须同时发布 `UNIVERSAL / STATIC_IMAGE` 和平台动态变体。
4. 动态作品公开详情同时返回动态与静态 capability，列表封面来自静态原图。
5. 同一需兑换作品只首次消耗一次兑换码额度；先下载动态、再下载静态时额度仍只增加 1。
6. 选择动态时只签发/下载动态包；选择静态时只签发/下载静态包。
7. 尝试为动态作品发布“仅动态”或“仅静态”组合时，API 在改变任何已发布版本前整体拒绝。
8. 4D 上传、封面、预览、下载和设置行为与当前版本一致，不出现动态/静态选择。

## 8. 本轮不变的范围

- 不新增兑换码类型、变体权益或两次兑换。
- 不修改 `FREE / REDEEM` 获取方式。
- 不把静态形式建成新的壁纸作品或分类。
- 不让 API 自动从 MP4 抽帧当静态原图；静态原图必须由内容管理员上传。
- 不修改 4D ZIP、配置透传、Lab 调参或不同轴运动算法。
- 不在本需求中实施卸载/重装后的自动权益找回；1.0 继续由客服核验后处理。
