**环境：** 本地 API/MySQL/Redis/FileStorage；127.0.0.1 与 localhost 两个浏览器来源使用独立 H5_TEST 设备。

## 1. 自动检查

H5 的 npm run check（19 个测试、Token、TypeScript）和 npm run build 通过。测试独立计算 UTF-8 HMAC/SHA-256，核验 Java Instant 时间串、challenge proof 与签名请求，验证会话并发复用和一次续期、敏感请求同 body/key 新 nonce、刷新恢复待确认记录、拒绝不同码或壁纸、202/404 结果保持待确认、422 业务结果处理，以及真实权益刷新/分页失败恢复。本工作包不修改 Java 或 OpenAPI。

## 2. 浏览器与业务事实

1. 首次访问“我的”自动完成真实设备注册、challenge 和会话，显示服务端空权益列表。
2. “联调晨雾”输入完整但不存在的码，真实 422 返回无效码，界面没有新增权益。
3. 管理 API 生成本地验收批次 3，1 个码、额度 3，并通过一次性交付后确认。127.0.0.1 浏览器兑换成功，后台记录 GRANTED / quotaDelta=1。
4. 成功后请求真实下载描述，仅收到 H5_PLACEHOLDER；演示完成明确说明未下载正式资源和未修改系统壁纸。
5. localhost 独立浏览器完成注册后，暂停本地 API 容器并提交兑换。15 秒超时后界面显示“兑换结果尚未确认”，保留原 key、清空输入框；恢复 API 后该请求在服务端完成。
6. 刷新 localhost 详情仍显示“确认兑换结果”，GET 原 key 确认 GRANTED，清除待确认状态。未重新 POST，后台只有这一个请求记录。
7. 后台批次 3 usedQuota=2 / totalQuota=3，码剩余额度 1；两条成功记录分别属于测试设备 2、3，每条 quotaDelta=1，壁纸 ID 都为 1。两个浏览器的“我的”均从同一服务端读取“联调晨雾”。
8. 1280 像素和 390 像素权益列表检查通过，无横向溢出，真实封面和客服二维码加载完成。临时尺寸已恢复。
9. 已获得详情再次点击“重新准备下载演示”，真实权益核验和占位演示成功；后台读回仍为 usedQuota=2 / totalQuota=3，没有新增兑换记录。
