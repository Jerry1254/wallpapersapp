## 实现范围

- 以私有库的 opaque installedId 调用类型化 Preview/WallpaperApply；不暴露文件路径。使用前重新验证原始 manifest 的 RSA 签名、安装身份和所有 payload 长度/哈希/普通文件与严格集合；指针存在不足以表示内容可信。
- 单进程资源库、同步提交/清理与可重复关闭的使用租约；保留预览、播放、待确认和已提交视频。创建第二个预览不会恢复或删除正在下载的暂存文件。
- App 内静态全屏居中裁切预览，按屏幕尺寸采样并检查内存；视频独立 Surface/MediaPlayer 静音循环，首次渲染后才确认已展示。退出预览不等于设置系统壁纸。
- 静态 WallpaperManager.setStream 的 HOME/LOCK/BOTH 三种 flags，禁止备份。比较返回 ID 与所请求位置的系统 ID；BOTH 的桌面 ID 匹配且锁屏无独立 ID 时，按 Android 共用画面语义确认。异常/不一致为 unknown，保留有可能已复制的资源供检查。
- 视频专用 WallpaperService，系统 ACTION_CHANGE_LIVE_WALLPAPER 选择页、待选与提交指针分离、先渲染再确认、取消保留旧内容。每个 Engine/预览独立播放器，不可见或 Surface 销毁释放，可见与进程重建复验并重新加载。
- 系统策略/解码器/入口能力查询；静态直接选择三位置，视频入口说明位置由系统选择。Android 14+ 查询 HOME/LOCK 实际组件；旧系统不申请广泛包可见权限，无法确认时为 unknown。两处使用同一倾境服务时共用同一视频，不能承诺独立视频。
- 详情/目录/权益页传递适配器，安全安装后显示预览和设置；符合最低系统且附加要求为空、有原生预览/设置入口时允许兑换。不从作品类型或服务器变体推导手机系统设置成功。
- SET_WALLPAPER；导出服务由 BIND_WALLPAPER 系统权限保护，预览 Activity 不导出。Manifest 检查覆盖这两个边界，未增加外部存储或 QUERY_ALL_PACKAGES。

## 验收条件与性能方案

工具链沿用 A00：Flutter 3.38.10 / Dart 3.10.9 / Temurin 17.0.19 / compile SDK 36，最低 API 26。模拟器 Android 35 x86_64 只作补充；现已通过无线 ADB 连接红米 M2012K11AC / Android 13 / arm64，手机端访问本地 8081 分类 API 返回 HTTP 200，正常 App 显示实际分类与壁纸，并完成正式身份请求和空权益读取。网络配置见 [OPS-002](../07-部署与运维/OPS-002-Android真机连接本地API.md)。API/数据库/OpenAPI 未修改，不涉及迁移；1.2.0 冻结保持。

A10 真机实测使用合法竖屏 1080×2400、H.264/yuv420p 无音轨、30 fps、10 秒循环素材，每台目标机记录实际系统设置选项。先暖机 5 分钟再测连续可见 30 分钟与不可见 10 分钟：首帧目标不超过 3 秒；不可见后 1 秒内停止播放器；可见段应用 PSS 增长目标不超过 20 MiB；不得有解码错误、崩溃或 ANR。同时记录电量/温度/CPU、系统基线和实际掉帧情况，数值目标不代表已经达到或功耗承诺。A07 的 512×512/30 fps/1 秒夹具不能替代该真机方案。

## 实测发现与修复

1. 首轮静态 HOME/LOCK 分别完成；BOTH 返回桌面新 ID、锁屏 -1，原判断误报 unknown。结合系统 dumpsys 的 `mWhich=3` 与 AOSP 共用画面处理，补齐这一返回形态并加入回归测试。
2. 预览标题与 Android 15 状态栏重叠。加入系统栏及显示切口 insets；复测截图确认标题和结束按钮均在安全区域内。
3. 首次视频系统预览崩溃：MediaPlayer.setDisplay 间接调用壁纸 SurfaceHolder 不支持的 setKeepScreenOn。改为 setSurface，按可见性控制播放且安全释放；后续实测系统预览播放正常。
4. 崩溃残留待选记录阻止重新设置。新协调流程放弃旧未确认指针、保留提交视频，重新进入设置成功。
5. 已观察并通过静态三目标、视频取消及视频桌面系统确认。该模拟器选择页仅有 Home screen 和 Home screen and lock screen，无独立锁屏；后者尚未实际设置。切回桌面后的组合测试出现异步等待停滞，已保留日志，正在定位并复测，不计整条剧本通过。
6. 后续复测出现系统 ANR 对话框，`dumpsys activity lastanr` 记录 MainActivity 焦点事件处理超时；Dropbox 主线程样本位于 Flutter/Dart native 执行。此前“测试异步等待”仅是排查假设，不能作为根因。已保存 `a07-last-anr.log`、`a07-anr-dropbox.log` 与截图；添加实际 Flutter 测试页、查询超时及 runAsync 尚未证明解决，A07 继续进行中，暂不提交为完成流程。
7. 用该构建的 x86_64 `libflutter.so` 与 NDK llvm-symbolizer 解析主线程地址，得到 `StubCode::GetAllocationStubForClass`、`AllocateObjectInstr::EmitNativeCode`、`FlowGraphCompiler::VisitBlocks`、`CompileParsedFunctionHelper::Compile`，样本处于 Dart JIT 编译；保留 `a07-anr-symbolized.log`。这不能单独证明全部停顿由 JIT 导致。当前 Flutter Loader 已拒绝 `DisableMergedPlatformUIThread`，未添加失效开关。重新冷启动本任务的只读临时模拟器，直接运行相同测试 APK，排查宿主测试连接的影响；结果待补。
8. 冷启动临时模拟器后，系统电话进程连续 ANR；切换 host GPU 后还出现 Watchdog 杀死 system_server 与多个系统应用 DeadSystemException。保留系统负载、崩溃和 Watchdog 输出。本任务已停止模拟器，未修改保存的 AVD，也不据此证明原应用 ANR 的唯一根因。
9. 红米系统选择器立即退出并记录 `No permission to change wall paper`。该机型系统 APK 的 LiveWallpaperChange 只读反汇编表明第三方应用需 AppOp 10045；系统“其他权限→动态壁纸服务”默认拒绝。经正常系统权限页面允许后预览与选择页打开。加入只读 OEM 权限预检和 setupMessage/重新检测入口：实机重新拒绝后 VIDEO targets 为空、apply 返回 unsupported 且不改变 ID；重新允许后能力恢复。不用 adb AppOps 强行授予，不申请额外短信/存储/包权限。
10. Android 13 实际选择视频后，系统记录已切换倾境服务，但 App getWallpaperInfo 返回 null，原逻辑报 unknown 并丢弃新播放指针。修正为：RESULT_OK + 已验证首帧、位置 API 不可读时保留新视频供已启用服务播放，仍报 unknown；取消/首帧未完成不替换旧视频。Android 14+ 可查询但未找到倾境服务时不提交，加入回归断言。老系统的宽权限限制依据 [WallpaperManager 官方说明](https://developer.android.com/reference/android/app/WallpaperManager#getWallpaperInfo())，未申请 QUERY_ALL_PACKAGES。
