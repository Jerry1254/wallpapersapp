# WP-OPS02 API 制品版本一致性验收

**日期：** 2026-09-17

**状态：** 已完成

**依据：** [OPS-007](../07-部署与运维/OPS-007-API制品版本一致性与发布门禁.md)

## 1. 问题复盘

8083 的健康检查一直为 `UP`，但实际运行的仍是 API 1.8.0 Jar，而源码、OpenAPI 和 App 已按 2.1.0 联调。旧 Jar 不包含设备能力上报路由，导致 App 测试返回 `NoResourceFoundException`。

问题的本质是没有把运行进程与 Git、API 源码、OpenAPI、Jar 和 Flyway 绑定；端口和 readiness 无法证明运行的是当前制品。

## 2. 已实施门禁

- `/actuator/info` 返回环境 ID、部署阶段、Git 提交、API 源码 SHA-256、OpenAPI 版本、Jar SHA-256 和 Flyway 目标版本。
- OpenAPI 契约检查会验证 API 运行时默认契约版本与 `openapi.yaml` 一致。
- `scripts/local-device-api.py deploy` 固定 LOCAL_DEVICE 的 8083/3311/6391/资源目录和三个 App scope，先执行完整 Maven `verify`，再生成不可变 Jar、原子换包、重启和回读验证。
- `scripts/local-device-api.py status` 只读核对正在运行的 API，未提交 API 变更返回 `UNCOMMITTED_API_CHANGES`，旧包或错包返回 `STALE_OR_WRONG_API`。
- 固定 ffmpeg/ffprobe 通过用户级 ASCII 路径桥接传给 Java，避免中文工作树路径在 macOS Java 子进程中失真。
