## 1. 实施结果

App 已从旧的单类型判断切换到“商品已发布能力 ∩ 设备有效能力”模型：

1. Android 原生插件提供 SDK、系统版本、厂商、机型、宿主系统族、运行方式、姿态传感器和可设置位置。
2. App 启动后使用现有设备身份对 `PUT /device/me/capabilities` 做签名上报，且只使用服务端返回的 `effectiveCapabilities`。
3. API 返回 `428 DEVICE_CAPABILITY_PROFILE_REQUIRED` 时，App 强制重新探测和上报，然后只重试一次原请求。
4. 分类、目录和详情均使用设备会话；教程仍保持公开读取。
5. 首页“4D动态”、“动态壁纸”、“静态壁纸”分别使用 `ANDROID + LAYER_PARALLAX`、`ANDROID + VIDEO`、`UNIVERSAL + STATIC_IMAGE` 精确筛选；精选和免费分别使用 `view=FEATURED` 和 `accessType=FREE`。
6. 列表不再根据当前标签删除分页结果，直接信任 API 的计数与分页；卡片和详情保留完整 `availableCapabilities`，同一商品仍只显示一次。
7. 详情页按服务端能力与本机最新原生能力交集，允许用户在同一权益下选择 4D、动态或静态形式，不重复兑换，也不预下载其他形式。
8. 预览票据和下载票据均传送用户已选择的精确 `deliveryPlatform + resourceType`，并校验返回的资源版本是同一组合。
9. 设置位置只开放 `availableCapabilities.placements` 与原生能力均支持的选项。真实设置完成后将证据升级为 `SUCCESSFUL_SET`；系统明确返回不支持时移除对应能力并重新拉取详情。用户取消不会被记为不支持。
10. 当前 App 没有持久化目录、详情或待用下载描述缓存，因此不存在旧 `profileHash` 缓存串用。未来如增加持久化缓存，缓存键必须包含全部查询参数和 `profileHash`。
