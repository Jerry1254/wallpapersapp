## 1. 交付结果

- V9 新增一对一 `device_capability_profile`，增加 `wallpaper_variant.enabled`，删除互斥的 `wallpaper.kind`。
- 管理后台把三选一类型改为五项独立设置能力，可在同一商品上组合 Android 4D、Android 动态、iOS 动态、鸿蒙原生动态和通用静态。
- 展示封面与设置能力分离；复用图片不会自动授予静态能力。
- 新增签名 `GET/PUT /device/me/capabilities`，服务端按宿主系统和运行环境过滤 App 上报。
- 分类计数、目录、搜索、详情、已获得列表、兑换前可用性、预览和下载共用设备能力交集。
- 早期鸿蒙兼容层可保留实测 Android 能力；新鸿蒙 Android 容器不会因 APK 可运行而获得 Android 系统壁纸能力。
- 预览和正式下载按一个精确 `deliveryPlatform + resourceType` 申请，不回退其他资源形式。
- OpenAPI 升级到 2.0.0，共 61 个操作、97 个 Schema，并冻结 32 个语义/迁移文件摘要。
- App 对接说明见 [API-015](../04-接口设计/API-015-设备能力目录与多形式交付App对接说明.md)。

## 3. 关键验收场景

1. 没有设备能力档案时目录返回 HTTP 428；完成签名上报后可读取。
2. `HARMONY_CLASSIC + ANDROID_COMPATIBLE` 保留上报的 Android 4D、Android 动态和通用静态能力。
3. `HARMONY_NATIVE + ANDROID_CONTAINER` 过滤 Android 4D/动态，只保留真实允许的通用静态能力。
4. 发布商品只返回当前设备命中的 `availableCapabilities`，分类数量与列表一致。
5. `minimumOsVersion` 不满足、请求其他平台组合或停用能力时，不签发该资源票据。
6. Android 静态资源使用 `UNIVERSAL / STATIC_IMAGE` 精确申请；4D/视频使用对应 Android 组合。
7. 同商品权益继续绑定 `deviceId + wallpaperId`，切换资源形式不重复兑换。
8. 管理端有资源历史的变体不能修改平台/资源组合，但可以独立启停。
9. 不存在安全包的 Android/通用正式资源不允许新兑换；票据读取继续复核作品、权益、凭据和资源版本状态。
10. 4D 导入、审计失败回滚、设置教程和既有安全包流程保持通过。
