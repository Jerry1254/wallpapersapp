## 1. 契约与自动测试

控制器映射测试读取冻结 OpenAPI，确认 WP-P08 的 18 个 HTTP 操作均有且只有一个 Spring Controller 映射。Java 快速测试共 17 项，覆盖既有存储边界、模块结构、管理内容契约和本阶段路由契约。

Testcontainers 集成测试使用独立 MySQL 8.4 与 Redis 7.4，通过真实 HTTP 完成 6 个大场景。本阶段新增场景同时验证：

- 同一批次幂等键顺序重试返回同一批次，异参返回 409。
- 同一批次幂等键并发提交只创建一批码，两个响应收敛到同一批次。
- CSV 只能使用短时票据读取；确认交付后返回 410，数据库没有完整码列和值。
- H5 测试设备注册、挑战、proof、短期 Bearer 会话和敏感请求签名通过。
- 同一兑换幂等键返回完全相同的 MySQL 最终结果，异参返回 409。
- 同一设备已拥有壁纸时返回 `ALREADY_OWNED`，不再次扣减额度。
- 3 台设备并发争抢剩余 2 个额度，结果严格为 2 次 `GRANTED` 和 1 次 `CODE_EXHAUSTED`；最终 `used_quota = 3`、ACTIVE 权益数为 3。
- 清空 Redis 后使用设备凭证重新建立会话，仍能从 MySQL 读回原兑换结果。
- H5 下载描述为 `H5_PLACEHOLDER`，不会返回伪造的正式下载票据或永久地址。
- 管理查询返回兑换、设备、凭证活动和权益，不含 secret/hash、证据 hash 或公钥材料。

## 2. 本地真实 API 与浏览器验收

本地 Compose 栈重建后，API、MySQL 和 Redis 均为 healthy/readiness UP。浏览器通过真实管理会话完成：

1. 创建 3 个兑换码、每码 2 个额度的批次。
2. 下载一次性 CSV，并由页面确认交付；列表状态立即变为“已确认”。
3. 打开批次详情，只看到 `*****-*****-*****-末五位`、已用和剩余额度。
4. 使用另一个批次注册 H5 联调设备，完成挑战应答、签名会话和一次真实壁纸兑换。
5. 兑换记录页读到 `GRANTED`、额度 `+1`、幂等键、壁纸与匿名设备。
6. 设备权益页读到 H5 凭证元数据和一条 ACTIVE 壁纸权益。
7. 页面树中没有 `secretHash`、`credentialSecret`、`evidenceHash` 或 `publicKeyPem`；779 px 宽窗口的文档宽度与视口宽度相同，无横向溢出。

验收临时脚本、管理员临时口令和备份文件已删除；管理员原密码哈希已经恢复。验收产生的批次、匿名设备、兑换事实和权益保留在本地开发数据库中，便于 WP-P09/P10 联调使用。
