# WP-P05 本地资源存储验收记录

**日期：** 2026-09-11

**结论：** 通过

**适用范围：** 本地 FileStorage Port、文件系统 Adapter、上传内容校验和受控读取

## 1. 验收映射

| 验收条件 | 实现与证据 | 结果 |
|---|---|---|
| 防路径穿越 | `StorageKey` 拒绝绝对路径、空段、`.`、`..`、反斜杠和盘符；读取使用真实路径并检查 `objects` 根边界；符号链接逃逸测试通过 | 通过 |
| 重名不覆盖 | 原文件名只清洗为展示元数据；正式对象键使用随机 UUID 和两级分片，同名内容连续上传得到两个不同对象并分别可读 | 通过 |
| 数据库不保存绝对路径 | `asset` 只包含唯一 `storage_key` 和文件元数据；契约测试禁止 `absolute_path`、`file_path`、`filesystem_path` 字段 | 通过 |
| 校验失败不进入正式区 | 输入流先写随机暂存文件，执行大小、探测类型、用途、MIME、内容结构检查；异常路径自动删除暂存文件 | 通过 |
| 内容完整性 | 暂存时计算 SHA-256，原子提交前重新核对文件大小和 SHA-256；正式读取只通过 `FileStorage` 返回受控流 | 通过 |

## 2. 上传校验基线

| 用途 | 最大大小 | 允许类型 |
|---|---:|---|
| `CATEGORY_ICON` | 10 MiB | JPEG、PNG、WebP |
| `WALLPAPER_COVER` | 20 MiB | JPEG、PNG、WebP |
| `BACKGROUND` | 50 MiB | JPEG、PNG、WebP |
| `FOREGROUND` | 50 MiB | PNG、WebP |
| `PARALLAX_CONFIG` | 2 MiB | JSON object |
| `VIDEO` | 200 MiB | MP4、QuickTime |
| `LIVE_PHOTO_IMAGE` | 50 MiB | JPEG |
| `LIVE_PHOTO_VIDEO` | 200 MiB | MP4、QuickTime |
| `STATIC_IMAGE` | 50 MiB | JPEG、PNG、WebP |
| `THEME_PACKAGE` | 250 MiB | ZIP |

图片校验覆盖 JPEG/PNG 实际解码、WebP RIFF 与尺寸边界，单图最大宽高 32,768 像素且最多 4,000 万像素。JSON 必须是单个对象。ZIP 最多 1,024 个条目，展开后最多 512 MiB，并拒绝路径逃逸和重复条目名。MP4/QuickTime 当前校验容器 `ftyp` 签名；编解码器、时长和转码检查属于后续资源处理流程，不作为本地落盘门禁。

测试覆盖：

- 输入流大小限制与半成品清理。
- SHA-256、受控暂存读取、原子提交和正式读取。
- 绝对路径、父目录穿越、Windows 分隔符、非对象命名空间和符号链接逃逸。
- 暂存文件在校验后被同大小篡改时拒绝提交。
- 同名文件不覆盖、原文件名不参与存储键。
- 图片解码与尺寸、用途类型限制、声明 MIME 伪装、JSON 语法和尾随根值。
- 安全 ZIP 接受、`../` ZIP 条目拒绝。
- Spring 上下文绑定本地存储配置，MySQL 空库迁移、Redis 与 readiness 回归通过。

## 4. 已知边界

本流程只建立资源校验与本地存储能力，不开放无认证上传 HTTP 接口。管理员鉴权、`asset` 元数据事务和管理上传接口在 WP-P06 接入。正式环境对象存储、视频转码、恶意内容扫描和衍生预览不属于当前本地 H5 数据闭环。
