## 1. 契约覆盖

自动契约映射测试读取 `contracts/openapi/openapi.yaml`，确认冻结契约中的 25 个管理身份与内容 HTTP 操作均有且只有一个 Controller 映射。兑换码、兑换记录和设备管理操作继续由 WP-P08 实现。

所有 JSON Long ID 均返回十进制字符串。管理 DTO 不返回 `asset.storage_key`、绝对路径、密码摘要、会话令牌或其他数据库内部字段。

## 3. 内容与发布验收

容器集成测试使用真实 HTTP、MySQL、Redis 和临时 FileStorage 完成以下链路：

1. 上传分类图标、壁纸封面和静态资源，确认 SHA-256、受控预览内容和响应无存储键。
2. 创建一级与二级分类，壁纸请求同时提交根分类和直属子分类，数据库只保存最深节点。
3. 创建 `STATIC + UNIVERSAL + STATIC_IMAGE` 变体和版本 1，角色绑定通过后版本进入 READY。
4. 使用当前壁纸 ETag 发布版本 1，壁纸进入 PUBLISHED 并返回一个派生交付能力。
5. 使用旧 ETag 更新壁纸返回 412 `VERSION_CONFLICT`。
6. 修改已有资源历史的变体返回 409 `RESOURCE_IN_USE`。
7. 创建版本 2 并重新发布；版本 1 原绑定保持不变且状态变为 RETIRED，版本 2 成为唯一 PUBLISHED 版本。
8. 下架后壁纸进入 OFFLINE 且版本 2 保持 PUBLISHED；归档后壁纸进入 ARCHIVED 且版本 2 退役。
9. 检查 Asset、分类、壁纸、变体与资源版本管理写操作均产生成功审计，数据库存储键保持相对形式。
