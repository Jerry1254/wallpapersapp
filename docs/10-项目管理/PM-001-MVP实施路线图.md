# PM-001 MVP 实施路线图

**状态：** 生效
**版本：** V1.1.0
**日期：** 2026-09-13
**关联需求：** PRD-WP-001
**关联架构：** ARC-001

## 1. 执行原则

1. 固定顺序为：H5 原型 → 管理后台 Mock → 数据库与 API → 混合 App → Android 上架。
2. H5 与管理端先验证交互，不在 Mock 阶段提前绑定数据库字段。
3. H5 和管理端通过 Repository 接口读取 Mock；切换真实 API 时不改页面业务结构。
4. App 正式工程从创建当天就是 Flutter + 平台插件结构，不先做纯原生正式版。
5. 同一时间只保留一个主要工作项进行中，前一阶段人工验收后再冻结下一阶段输入。
6. iOS、HarmonyOS 的接口骨架与平台资源模型首版建立，功能实现不进入 Android 首发范围。

## 2. 最终链路

    管理后台维护分类、壁纸和资源版本
                    ↓
    管理后台生成兑换码批次并一次性交付客服
                    ↓
    Java API 执行设备、兑换、权益、下载和审计规则
                    ↓
    MySQL 保存事实，Redis 协调短时状态，首阶段本地目录保存资源
                    ↓
    Flutter App 浏览、预览和兑换
                    ↓
    Android 原生插件安装并进入系统壁纸设置

## 3. 阶段门禁

| 阶段 | 结果 | 必须满足的退出条件 |

## 8. Android 首发验收矩阵

至少覆盖以下厂商各一台近三年常用机型：

- 小米或 Redmi。
- 华为仍运行 Android/EMUI 的机型。
- OPPO 或一加。
- vivo 或 iQOO。
- Samsung。
- Android 模拟器仅用于基础回归，不代替真机动态壁纸验收。

每台设备验证：

1. 冷启动和匿名设备注册。
2. 分类、详情与倾斜预览。
3. 首次兑换和额度扣减。
4. 下载中断、重试、哈希及签名校验。
5. 设置桌面、锁屏或系统实际提供的范围。
6. 重启手机后壁纸仍工作。
7. App 进程结束后壁纸服务仍由系统托管。
8. 卸载重装后的同设备权益恢复。
9. 无权益设备无法复用下载地址。
10. 资源更新和旧版本清理。

## 9. 阶段变更规则

- H5 人工验收前可以调整页面结构和视觉方向。
- 管理端人工验收前可以调整运营字段和操作路径。
- WP-W11 开始后，字段语义变化必须同步领域模型、数据库、OpenAPI 和两端映射。
- WP-W17 开始后，平台能力新增必须通过 WallpaperPlatform 接口，不允许在 Flutter 页面直接调用 Android 通道。
- 已生成兑换码的 totalQuota 不接受批量追溯修改；补偿通过独立、受审计的管理操作完成。
- 已发布资源版本不覆盖，只能发布更高版本或紧急下架。
