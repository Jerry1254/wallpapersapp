## 1. 目标

在开始 Flutter App 之前，先使用真实数据库和 API 打通以下闭环：

1. 管理员登录管理后台。
2. 管理员维护一级、二级分类并上传本地资源。
3. 管理员创建、发布、下架壁纸并生成兑换码。
4. H5 从 API 读取分类、列表、搜索、详情和已获得壁纸。
5. H5 使用测试设备身份完成兑换，MySQL 正确记录额度、权益和兑换事件。
6. 管理后台可查看 H5 产生的兑换、设备和权益数据。
7. API 契约冻结后，Flutter App 直接复用目录、兑换、权益和下载 API。

## 2. 已确认的阶段边界

- 所有图片、视频和分层资源先保存在 API 服务器的本地资源目录。
- 通过 `FileStorage` 接口和本地 Adapter 访问文件，数据库只保存资源 ID、存储键、哈希、格式、大小和版本。
- 运行时文件默认位于 `.runtime/storage`，不进入 Git；后续切换 S3 兼容存储时不改数据表和业务 API。
- H5 详情页暂时使用封面或占位演示，不接入真实 4D 姿态、动态视频播放和系统壁纸设置。
- 真实预览衍生、加密资源包、对象存储和 CDN 在 H5 数据闭环后实现。
- H5 设备身份只用于本地和测试联调。正式 App 使用 Android Keystore 或其他平台安全存储生成的设备凭据。
- 本阶段不实现支付、多租户、RBAC、iOS/HarmonyOS 原生能力和生产发布。

## 3. H5 与 App 复用关系

| 能力 | H5 联调 | 正式 App | 是否共用 API |
|---|---|---|---|
| 分类、列表、搜索、详情 | 真实数据 | 真实数据 | 是 |
| 兑换码核销 | 真实事务 | 真实事务 | 是 |
| 已获得壁纸 | 真实权益 | 真实权益 | 是 |
| 下载描述与版本 | 返回测试描述 | 返回安全下载描述 | 是，返回能力有差异 |
| 设备身份 | 浏览器测试 Provider | 平台安全 Provider | 接口一致，证据强度不同 |
| 4D/动态预览 | 封面或占位效果 | Flutter + 原生插件 | 只共用资源描述 |
| 系统壁纸设置 | H5 模拟交互 | 原生系统能力 | 否 |

H5 中的“已下载”和“已设置”仅用于交互演示，不作为服务端权益事实。服务端只以兑换成功后的设备壁纸权益为准。

## 6. 实现顺序

1. WP-P00：建立可追踪计划并推送当前工程基线。
2. WP-P01 至 WP-P03：先冻结领域、数据库和 API 契约，不先写 Controller。
3. WP-P04 至 WP-P05：建立可重复启动的本地 API、MySQL、Redis 和文件存储。
4. WP-P06 至 WP-P07：先让管理后台真实写入内容数据。
5. WP-P08：完成设备、兑换码和权益的服务端事务。
6. WP-P09 至 WP-P10：H5 读取后台数据并完成真实兑换。
7. WP-P11：使用端到端脚本验证完整闭环。
8. WP-P12：冻结契约后开始 Flutter App。

## 7. H5 闭环验收剧本

1. 使用管理员账号登录。
2. 新建一级和二级分类，上传分类图标。
3. 上传一张 4D 壁纸的封面、前景、背景和配置文件并发布。
4. 在 H5 首页、分类、搜索和详情中查到该壁纸；详情页允许显示封面占位效果。
5. 在后台生成一批单码额度为 3 的兑换码。
6. H5 设备 A 兑换该壁纸，兑换码已用额度变为 1。
7. 设备 A 重复兑换或下载，额度仍为 1。
8. 设备 B、C 分别兑换，额度最终为 3；设备 D 无法再获得新权益。
9. 后台兑换记录、设备列表和 H5“我的”页面展示一致。
10. 重启 API、MySQL 和 Redis 后，已发布壁纸和权益仍可查询。

## 8. 测试门禁

每个大流程至少完成：

- 编译和静态检查。
- 与该流程风险相匹配的单元、集成或端到端测试。
- 空数据库初始化和已有数据升级验证。
- 错误响应、边界值、重试和并发行为验证。
- 敏感信息、运行时资源和生成产物未进入 Git。

未执行的检查必须在验收记录和任务状态中同时说明。

## 9. Git 同步规则

- `main` 只保存已通过当前阶段检查的可运行基线。
- 每个 WP-Pxx 可包含多个本地开发提交，但完成整个大流程后必须将最终状态推送到远程。
- 提交信息使用 `docs:`、`feat(api):`、`feat(admin):`、`feat(h5):`、`test:` 或 `chore:` 等明确前缀。
- 推送前记录所运行的检查与结果。
- 禁止提交 `.env`、`.runtime`、本地数据库、上传资源、密钥、打包产物和依赖目录。
