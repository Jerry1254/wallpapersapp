# 倾境创作台测试用例与壁纸管理后台联动验收

本用例用于验收创作台从素材导入、壁纸加工、内容创作到账号分发的完整流程，以及壁纸上传、资源处理、资料更新和上架与管理后台的联动。按下列步骤操作，在配套执行记录表填写实际结果、截图和缺陷编号。生成成功、上传成功、上架成功、平台确认发布是不同的结果，必须分别核对。

## 1 执行说明

### 1.1 测试范围与结果口径

- 创作数据由本地创作服务负责，包括项目、素材、模板、收藏、作品和生成任务。浏览器中的自动保存内容用于编辑恢复；未连接后台时的浏览器保存，不代表已经写入后台。
- 壁纸后台负责正式资产、壁纸资料、平台资源版本、获取配置、预览和上架。素材库中的文件或已经生成的视频，不等于 App 正式交付资源。
- 社交分发仅覆盖抖音和小红书的图文与视频，不包含保存平台草稿。创建壁纸弹窗当前仍包含“保存草稿”，它保存的是壁纸后台资料，单独验收。
- “导出视频”下载本地 MP4；“生成作品”预览后“保存至发布内容”保存成品并关闭弹窗，留在当前工作区。作品库的“下一步”才进入内容发布。
- 社交任务“已提交”和“结果待核对”不能计为“已确认发布”。点击平台提交后连接中断，不允许自动重新发布。
- 统计按任务创建日期和当前状态汇总，日期使用北京时间。账号指标是有采集时间的累计值，不能把每天的累计快照相加；缺少值或基准时显示“—”。
- 本次文档不扩展到 App 全量测试、生产部署、Apple 实际支付、自动爬取全平台作品数据或其他平台发布。必要的正式资源读取列为联动检查。

| T1 | 本地测试素材集已准备好，详情见下一节 |
| R1 | 本地 API 和浏览器开发者工具可用；由开发人员实施请求拦截、响应丢失或故障注入 |

表内多个代号均需满足。A1 / A2 用例涉及真实平台账号和网络；未具备账号、短信验证、素材权限或所需平台选项时标记“阻塞”，不得标记通过。R1 操作只针对测试数据，不直接修改业务数据库。

优先级：P0 为主流程、数据安全、错账号发布、重复发布和正式资源正确性；P1 为常用编辑、查询、恢复和校验；P2 为辅助交互与性能观察。结果填写“未执行、通过、失败、阻塞、不适用”。“不适用”须写明原因。

真实账号发布、后台上架、下架和归档会产生业务变化。先指定测试账号和测试壁纸，使用自有或已授权素材；执行人只在最终确认清单无误后点击发布。短信和验证码由账号本人填写，记录截图须遮住二维码、手机号、密码、Cookie 和 Token。

## 22 缺陷记录与通过标准

### 22.1 记录规则

执行记录表一行对应一条用例，可筛选模块和优先级。操作遇到失败时，保留当前状态，记录具体步骤、实际结果和可复现条件；不要反复点击发布或创建新的替代任务来掩盖异常。

每个缺陷至少记录：用例 ID、环境与版本、执行时间、项目或任务标识、复现步骤、预期与实际结果、截图或脱敏日志、严重程度和复测结果。发布异常另记是否已点平台提交、平台作品是否实际存在；上架异常另记商品 ID、资源版本和预览状态。

严重程度建议：S1 为数据丢失、泄露、错账号、重复发布、源资源错误或越权；S2 为主流程无法完成或恢复失败；S3 为常用功能错误但有明确替代操作；S4 为提示和排版问题。优先级 P0 / P1 / P2 是执行顺序，与缺陷严重程度不混用。

### 22.2 推荐执行顺序

1. 核对 ENV 和 SEC 的连接、环境与认证，再做 PRJ 项目保存恢复。
2. 做 WST、WTM、W4D 壁纸加工和 IMG、CMP、TPL 图片编辑。
3. 做 VID、VTL、LIB、WRK、JOB，确认成品文件及保存语义。
4. 做 PUB、RES、REC、ADM、IOS，重点核对后台商品 ID、正式资源与预览。
5. 做 ACC、FORM、BAT；确认测试账号与内容后执行 RUN 四种真实发布。
6. 做 HIS、DAT、BAK、STB 和六条 E2E，再回归修复涉及的用例。

### 22.3 本轮验收通过条件

- 所有适用 P0 用例通过，不能存在未解释的阻塞；S1 和 S2 缺陷关闭并复测。
- 六条端到端流程通过；真实账号四种发布组合均在平台页面核对，平台要求导致暂不可测的场景须单独列出，不计为通过。
- 后台资料、商品状态、正式资源版本和预览状态分别核对；文件内容、尺寸、帧率和声音有证据。
- 重复点击、响应丢失、重启恢复和后台并行修改不会导致重复业务结果或覆盖较新资料。
- 项目备份恢复可用且不包含凭据，不会复活原发布请求或商品更新关联。
- P1 / P2 未关闭项列明影响、替代操作和处理决定。性能结果给出实测机器和输入，不能用“本地理论更快”代替测量。

既有自动化回归用于辅助证明帧映射、渲染、幂等、版本冲突和统计等规则。它不替代本表人工执行，也不替代真实账号发布、短信验证和管理后台界面联动核对。执行记录默认全部“未执行”，由执行人填写结果。
