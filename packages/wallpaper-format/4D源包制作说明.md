# 4D 壁纸源包制作说明

4D 效果在 Web 模拟器中完成调整，然后导出一个 ZIP。管理后台只上传完整 ZIP，不在后台重新编辑位移参数。

## 固定目录

```text
wallpaper.zip
├── cover.jpg
├── config.json
└── layers/
    ├── 01.png    最前景
    ├── 02.png    中间图层
    └── NN.jpg    最后一层为完整背景
```

- 支持 2～12 层，编号从 `01` 连续递增；所有图层使用同一画布尺寸。
- 前景使用带透明通道的 PNG 或静态 WebP；最后背景必须完整不透明，可使用 PNG、JPEG 或静态 WebP。
- `cover.jpg` 是列表和详情展示的合成封面，不参与 4D 分层播放。
- ZIP 内直接放上述内容，不要再包一层外部文件夹。

## 签名位移规则

`offsetPercent` 直接表示图层在满幅倾斜时，相对屏幕对应轴的移动百分比：

- 正数：跟随手机倾斜方向。
- 负数：向手机倾斜的反方向移动。
- 0：保持不动。

二层项目默认可使用前景 `+8%`、背景 `-3%`。多层项目在 Web 模拟器里逐层拖动数值，软件不根据图层编号自动猜测前后运动关系。

## config.json v2

```json
{
  "formatVersion": 2,
  "canvas": { "width": 2048, "height": 2048 },
  "motion": { "maxAngle": 75 },
  "layers": [
    { "index": 1, "offsetPercent": 8, "scale": 1.18, "opacity": 1, "blendMode": "normal" },
    { "index": 2, "offsetPercent": 2, "scale": 1.18, "opacity": 1, "blendMode": "normal" },
    { "index": 3, "offsetPercent": -3, "scale": 1, "opacity": 1, "blendMode": "normal" }
  ]
}
```

| 字段 | v2 范围 | 含义 |
|---|---:|---|
| `canvas.width/height` | 512～4096 | 与每张图层的源像素尺寸一致 |
| `motion.maxAngle` | 1～75° | 达到每层配置位移量所需的相对倾斜角 |
| `index` | 1～12 连续 | 与 `layers/NN` 文件对应 |
| `offsetPercent` | -25～25 | 正数跟随、负数反向、0 固定 |
| `scale` | 1～1.5 | 图层显示放大系数 |
| `opacity` | 0～1 | 图层整体不透明度 |
| `blendMode` | `normal` / `screen` / `add` | 图层合成方式 |

正式 Android 壁纸按源图层分辨率解码，不静默降采样。背景显示时会根据最大移动量预留边缘，这是绘制阶段的显示放大，不会改写、压缩或降低源图质量。

Schema：[`parallax-source-v2.schema.json`](parallax-source-v2.schema.json)。当前链路只接受 v2，v1 `depth/strength` 包不再导入或播放。

## 后台与 API 边界

按 API-008 改造后，API 检查 ZIP 和图片文件是否完整、安全，然后原样保存和签名 `config.json`。API 不校验位移正负、不判断效果好坏，不把配置转换为另一套内部算法字段。详见 [API-008](../../docs/04-接口设计/API-008-4D配置透传与管理后台改造方案.md)。
